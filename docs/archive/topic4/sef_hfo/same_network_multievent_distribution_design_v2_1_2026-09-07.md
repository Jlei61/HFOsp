## 2. 最小修改主排序统计量

保留 v2 的 `phi(e)`、质量敏感 `psi_k(e)=1[c(e)=k]/p_k * [1,phi(e)]`、患者目标、两个训练分量以及0.5/0.5权重。`p_k` 仍来自患者 FIT，当前为约0.3341/0.6659；这一归一化不自动保证有限样本目标的最优比例就是患者比例。

旧式

`D16 = ||mean(X)-t||² + (N-16)/(16*(N-1))*V_N`

确为固定样本无放回抽取16事件后均值平方差的期望。但在独立同分布的目标性质检查中，`E[D16]=||mu_Q-t||²+v_Q/16`，因此含有生成特征方差代价。它保留为**有限事件评分诊断**，不再用于DE更新或正式提名。旧枚举检查与原0.67/5.54对照不作为修订目标正确性的证明。

主排序改为**去自配对的经验训练统计量**：

`D_off(X,t) = ||mean(X)-t||² - V_N/(N-1)`，`V_N=mean_i ||X_i-mean(X)||²`。

它等价于将 `X_i dot X_i` 从模型自配对和中移除。有限样本可为负，**不得做 max(0,·)、取绝对值、开平方或只输出非负部分**。固定有限患者目标下，在独立事件理想检查中可去掉模型自配对偏置；对连续相关事件仅使用上述经验名称，不宣称对真实连续动力学生成分布无偏。有限RFF映射也不保证唯一识别所有生成分布。[Gretton et al., 2012，§2.2](https://www.jmlr.org/papers/volume13/gretton12a/gretton12a.pdf)讨论去对角估计及其有限样本负值。

主 loss 为每训练单元独立计算后等权平均：

`L_off = mean_unit [0.5*D_off_global/a_global + 0.5*D_off_modes/a_modes]`。

继续使用已冻结的正尺度 `a_global=0.0425770294722167`、`a_modes=0.21306191302831015`，来源为 v2 `loss_qualification.json` 的患者CAL、D16抽样中位数；不重新用可能为负或近零的 D_off CAL 中位数作除数。

本轮排名仍要求每个训练单元实际 N≥16；不足时 loss=null、不进入正式总榜。**16是本轮可估计性约定，不是 D_off 的数学下限（数学上N≥2即可），也不是每个候选实际证据量都相同。** 一个训练单元不足时不只平均另一个单元。

每条结果同时保存 `N_actual`、逐模式数量、`D_off_global/modes`、`D16_global/modes`、二者原尺度和归一化总分、各训练单元分数。另按每个运行、每个训练分量分别保存 `A=||mean(X)-t||^2` 与 `B=V_N/(N-1)=16/N*(D16-D_off)`，再按原0.5/0.5权重汇总；A/B只解释低分来自均值接近还是有限事件减项，不进入排序、惩罚或门槛。任何评分失败不得伪造0或随意大数写入科学结果。

当前代码已具有 `--topology-seed/--dynamics-seed` 接口，`build_substrate` 按拓扑seed取图，worker为模拟rng和空间OU传动力学seed；`kick_probe` 当前从V_reset初始化。应复用这些接口并检查实际数组，不重新设计模型。记录global/空间/Poisson流的派生关系；两种噪声流使用同一master并不等于数学独立流。四次运行只提供两个图上的有限重演证据，不能精确分解全部随机效应。

同一条件同一拓扑的两次动力学重演须验证静态数组完全一致、保存的dynamics seed不同且动态输出确实不同。跨候选即使整数seed相同，也只称“共用seed”；除非另有随机调用轨迹/前缀证明确认逐创新对应，不称严格共同随机输入。[NumPy 随机流兼容性说明](https://numpy.org/doc/stable/reference/random/compatibility.html)同样要求 BitGenerator、方法调用序列及调用参数等条件一致，而非只看整数seed。恢复索引和哈希验证能防止重复派发与输入漂移，但不冒充独立重复的完整执行可复现性检验；本轮不为此突破156次正式预算或重写噪声生成器。

## 8. 资源、失败与重启

最多8worker，不默认派满。`RLIMIT_AS=18GiB`只限制进程虚拟地址空间并影响mmap等调用，不是物理RSS预算。[Linux getrlimit说明](https://man7.org/linux/man-pages/man2/getrlimit.2.html)。8×18＋8GiB分析＋40GiB余量已达192GiB，还须预留其他任务未来增长、缓存、压缩和GIF阶段。

G0监测整个进程树的RSS/PSS（可用时）、虚拟地址空间、实际峰值、子进程、输出/临时文件增长和压缩阶段占用。有可用delegated cgroup时按真实memory controller核算和限制，核对实际文件生效；没有权限或控制器时用进程树监测＋保守准入。cgroup的memory.peak含子进程，不能用主进程单点RSS冒充峰值。[Linux cgroup文档](https://docs.kernel.org/admin-guide/cgroup-v2.html)。按实测峰值加余量和其他进程增长预留动态派发；分析/GIF也占用并发预算，磁盘至少保留30GiB并预测剩余输出。

结果同时保存 `physical_status` 与 `execution_status`：如已有观测满足runaway可与OOM同时为真；没有足够数据则physical_status=unknown。不得把OOM一律当成runaway，也不得因runaway便隐藏工程OOM。工程失败停新派发并收尾，保留日志、部分数据及物理可判证据；正常科学上拟合差或事件少不暂停G1。

重启恢复已落盘的候选、后代随机数、父代快照、seed pair及排序版本，不重抽。canary复用必须核对物理参数、静态数组、噪声seed、观测器、实际时长及原始输出合同；仅换离线loss可重评分复用。改变物理/读出或时长时另判兼容性；文件名存在或JSON标complete不足以复用。
