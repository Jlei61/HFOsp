## 2. 首轮 B0 判 FAIL 后查出的三件事

首轮两个 seed 都判 `STOP_ELR_BASELINE_VISIBLE`，但 **seed3 的执行器从未启动**
（`q_max` 157.66 < `Q_on` 173.43，占空比 0）且事件统计逐位相同 —— 在一个什么都没发生的
run 上失败，说明失败的是度量。审计后查出两处**我偏离锁定契约**、一处**契约内部矛盾**。

### 2.1 `Q_on` 只用了前半段事件（我的偏差，已修）

`CAL_SPLIT_FRAC` 管的是 `b_v`（plan §4.1 用标定前半段估背景包络）；plan §4.2 写的是
pass 2 重放"同一条记录"、取 `max_{event, occupied voxel}`，**没有半段限制**。
`run_topic4_fcxr_hyb2.py` 在**两个**调用点（`cmd_calibration` 与 `cmd_finalize`）都写了
`on[on < n_half * blk]`。后果：seed1 的 `Q_on` 小了 1.51 倍，而这恰好打破了 plan §7.1
用来声明第 1、2 条"按构造通过"的那个前提。

修法不是改那两行：把循环收成**一个**受测辅助函数 `H2.event_peak_values`，两个调用点共用，
所以不可能再各自漂移。

- seed1：`Q_on` 112.5047 → **169.8460**
- seed3：173.4290 **不变**（它最大的事件峰值本来就落在前半段）
- `τ_R` 30.5411 ms **不变**、`b_v` **不变**

### 2.2 第 2、3 条用了跨体素最大值而非契约的联合分位（我的偏差，已修）

契约写的是"q99（跨事件×占据体素）"。原实现先把每个块归约成 `max_v q_v` 再对它取 q99 ——
**1000 个体素上的最大值不是它们的 99 分位**，在 seed1 上偏高 2 倍。
这与 B2.1 幅度子句是同一类错误（时间 q99 套在空间 max 上），修法相同：B0 现在记录 load、
离线重放逐体素 `q`，与 calibration pass 2 完全同一条路径。

### 2.3 第 2 条的判词与 `b_v` 规则互相矛盾（**契约内部问题，未动**）

plan §7.1 第 2 条的推导是

> `q_peak · exp(−GAP/τ_R) ≤ 0.01 · Q_on` ⟺ `exp(−GAP/τ_R) ≤ 0.011`

它成立的前提是 **gap 内 `e_v ≡ 0`**。但 plan §4.1 定义 `b_v := Q99_t[s_v]`，按构造保证
**每个体素都有 1% 的块高于自己的 b_v**（实测占空比中位数 0.0074、90 分位 0.0103、
最大 0.0120，与 Q99 预言一致）。两条不能同时成立。

## 3. 第 2 条到底测到了什么（`figures/b0_gap_resolved_envelope_seed1.png`）

把契约那一个采样点摊开成整条 gap 的曲线，只采"距上次 offset ≥ 4τ_R"的点（此时上一次事件
的衰减余量 < 2%，任何高值都不可能是它）：

| 距 onset | q99/`Q_on` | 贡献 gap 数 | |
|---|---|---|---|
| 200 ms | 0.262 | 23 | FAIL |
| 100 ms | 0.010 | 32 | 临界 |
| 75 ms | 0.0051 | 33 | PASS |
| 50 ms | 0.0030 | 33 | PASS |
| 40 ms | 0.0029 | 33 | PASS |
| 30 ms | 0.0036 | 33 | PASS |
| 25 ms | 0.031 | 33 | FAIL |
| 10 ms | 0.088 | 33 | FAIL |
| **2 ms（契约窗）** | **0.161** | 33 | FAIL |

**包络确实清空了** —— onset 前 30–75 ms 是 0.0029–0.0051，过门。第 2 条不过来自另外两件事：

1. **下一次事件自己的局部爬升**。全局事件判据条是网络级的，局部体素必须先烧起来才能把全局率
   推过条；那段约 25 ms 的爬升正好落在 onset 前 2 ms 的契约窗里。
2. **gap 深处够不到全局判据条的局部活动**（200 ms 处 0.262）。它们在体素尺度上是真放电，
   只是不算"事件"。

两者都在执行器阈值以下（`q_max` < `Q_on`，占空比 0），所以**不影响执行器是否在基线上启动**。

> **本文档早前版本的一处更正**：首轮诊断（未加"距上次 offset ≥ 4τ_R"守卫）曾判定
> "残留是 Q99 规则的内在产物"。加守卫后静息地板是 0.0029（**过门**），
> **Q99 的 1% 占空比不是第 2 条不过的原因**。前一判断作废。

## 4. 需要裁决的问题

第 2 条按字面不过，整体 `STOP_ELR_BASELINE_VISIBLE`。但：

- 门的**名字与目的**问的是"这一层在基线上看得见吗" —— 答案是**看不见**（占空比恰好 0、
  事件统计逐位相同），且这是 `Q_on = 1.10 × 间期峰值` 的构造保证；
- plan 自己把第 2 条列为**不是独立证据**，把第 3 条列为**主判据**，而第 3 条通过；
- 第 2 条的推导前提与 `b_v = Q99` 冲突（§2.3），它测到的是**下一次事件的爬升**而非上一次
  事件的残留（§3）。

**改门 / 改窗 / 改阈值都属于设计锁修订，是 spec 作者的权限。** 本分支不动第 2 条，
不调 `Q_on` / `τ_R` / `I_R,max` / drive / 连接（plan §7.1 明令禁止），停在这里。

三个可能的裁决方向（不预设倾向）：
- **(a)** 维持第 2 条原样 → B0 判 FAIL，HYB2 在此收口；
- **(b)** 认定第 2 条的采样窗与其推导前提不符，改为在"静息窗"（如 onset 前 30–75 ms，
  或"距两侧事件均 ≥ 4τ_R"）上测同一个统计量 → 需以修订版 spec 重新预注册后再判；
- **(c)** 认定第 2 条既非独立证据、其前提又已被 `b_v = Q99` 证伪，降为诊断项不入门 →
  B0 由第 3、4、5 条判定，即通过。
