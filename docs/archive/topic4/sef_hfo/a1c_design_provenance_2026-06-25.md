## HOLE 1 (parity, FATAL as written): the sha256 guard hashes the WHOLE FILE — any new code path, even unreached at gain=0, re-blesses

The design's headline parity argument is "subtracting a zero array is not float-identical, so short-circuit `if i_global==0.0: I_net=I_E-I_I`, then run a full-trace `np.array_equal` regression, then re-bless." That conflates two different parity notions and gets the binding one wrong.

The guard is `src/sef_hfo_snn_engine_guard.py::assert_versions` → `_sha256(path)` over `Path(path).read_bytes()` — **the entire byte content of `kick_probe.py`**, compared to `engine_versions.json["src/snn_engine/kick_probe.py"] = "f7676b78…"` (I verified current file hashes to exactly that). The instant you add ANY character to `kick_probe.py` — the new `i_global` kwarg, the short-circuit `if`, a comment — the sha256 changes and **every M1/M2/M3/A1b run refuses to start until you re-bless**. So:

- The design's "off-by-default ⇒ bit-parity ⇒ no re-bless needed" framing is **structurally impossible for an in-file edit**. Re-bless is mandatory the moment you touch the file, regardless of float-identity.
- "Bit-parity" here therefore does NOT mean "skip re-bless." It means: after you re-bless, the *numerical outputs* of every gain=0 caller must be byte-identical to the pre-edit outputs. The sha256 guard cannot verify that — it only proves the source text is the reviewed text. The numeric-parity proof is a **separate, manual obligation** the design leaves implicit.

**Fix:** State the contract as two enforced steps, not one. (a) Numeric parity gate: a regression test that runs at least one M1 cell, one A1b cell, AND one plain cm-spontaneous cell at `feedback_gain=0` through both the pre-edit and post-edit engine and asserts `np.array_equal` on `E_spk_bool` AND `rate_E` AND `spk_inside/outside` (not just rate_E — see Hole 2). (b) Only after that passes, re-bless by recomputing sha256 and overwriting the one key. The design says "recompute sha256… (current f7676b78 → new)" — correct mechanism, but it must be gated behind the numeric test, and the doc must drop the implication that gain=0 avoids re-bless. It never does for an in-file change.

## HOLE 2 (parity, REAL): the short-circuit guards the wrong line, and the RNG/recorder stream is the actual parity risk, not the subtraction

Two sub-problems:

**2a — the zero-array subtraction is not where parity breaks.** The design worries `I_E - I_I - 0` differs from `I_E - I_I`. But the proposed injection is "pass an effective `I_I = I_I + I_fb` into the existing `membrane_step` subtraction." If you build `I_I + I_fb` where `I_fb = np.where(is_E, I_global, 0.0)`, then at gain=0, `I_global` is a *scalar 0.0* broadcast, `I_fb` is a fresh allocated zero array, and `I_I + I_fb` is a NEW array object even though values match — and `membrane_step` then does `I_E - (I_I+I_fb)`. Floating-point `x - (y + 0.0)` == `x - y` bit-for-bit for IEEE doubles (adding +0.0 is exact, no rounding), so values are safe — BUT only if you genuinely short-circuit. The design's short-circuit is written on the wrong line: it guards `I_net = I_E - I_I` inside `membrane_step`, but the `I_I + I_fb` construction happens in the *caller* (the loop body), before `membrane_step` is even called. If that construction runs unconditionally at gain=0, you've allocated arrays and done adds that didn't exist before — values identical, but see 2b.

**2b — the binding parity risk is the RNG draw order and recorder allocations, which the design never addresses.** Look at the loop: `rng.standard_normal()` (line 202), `rng.poisson(...)` (line 219), and the `ras_keep = rng.choice(...)` setup (lines 183–184) all consume the SAME `net["rng"]` stream. The M1 precedent (lines 172–179) is explicitly documented as parity-safe because at `ee_std_u=0` it does "no allocation, no new RNG draws, no float touches." A1c MUST meet that same bar. The EMA itself draws no RNG (good), but if the A1c block is inserted such that any array is allocated or any branch changes *before* the poisson draw at gain=0, you're fine on values but you've changed the allocation pattern — which is cosmetically harmless but means your `np.array_equal` regression in Hole 1 is the ONLY thing standing between you and a silent drift. The design's parity claim rests entirely on a regression test it describes in one clause; that test is load-bearing and must be elevated to a hard contract, not a "mandatory FULL-trace regression" footnote.

**Fix:** Gate the ENTIRE A1c block (EMA state init, per-step EMA update, `I_fb` construction, the `membrane_step` call-arg change) behind `fb_on = feedback_gain > 0.0`, exactly mirroring `ee_std_on = ee_std_u > 0.0` (line 174). At `fb_on=False`, the loop body must take the literal pre-edit `membrane_step(V, I_E, I_I, decay_V, …)` call with NO `I_fb` term constructed. Do NOT route gain=0 through `I_I + I_fb`. This makes the gain=0 path textually the old path (modulo the guarding `if`), so the only re-bless obligation is the sha change, and numeric parity is by-construction, not by-array_equal-luck.

## HOLE 3 (EMA correctness, REAL off-by-one): `rate_E[t]` is recorded AFTER the membrane step, so reading it "this step" reads the future

The loop order is: line 246 `membrane_step` (produces `spk` for step t) → line 257 `rate_E[t] = spk[:NE].sum()`. The membrane step that A1c must influence happens at line 246. The count for step t doesn't exist until line 257. So an EMA injected at line ~229 (before the membrane step) can only legitimately use counts from steps `≤ t-1`.

The design says "one-step causal delay carried as a scalar r_prev reused FROM the existing `rate_E[t]=spk[:NE].sum()` recorder line." That is correct ONLY if `r_prev` is updated at line 257 (end of step t) and consumed at the top of step t+1. If instead someone reads `rate_E[t]` at the injection point (line ~229) thinking "use this step's rate," they get the previous step's stale value if line 257 hasn't run, or — worse, if they move the EMA update below line 257 and also inject below line 257 — they create an **acausal feedback** where I_global at step t depends on spk at step t (the same spikes it's supposed to suppress). At dt=0.05ms scale this is a within-step instantaneous loop that can either over-damp (kills the event → fake "termination") or under-damp.

**Fix:** Specify the EMA as an explicit scalar state with a named update site: initialize `r_ema = 0.0` once; at the TOP of each step (before line 246) compute `I_global = feedback_gain * r_ema` and apply it; then at line 257 (the existing recorder) do `r_ema += alpha_fb * (rate_E[t] - r_ema)` using the count just recorded. This guarantees I_global at step t is a function of spikes at steps ≤ t-1 — a true one-step causal delay, the same discipline as the delay ring. The design's prose is compatible with this but must pin "consumed at top-of-step, updated at the recorder line" or an implementer will close the acausal loop.

## HOLE 4 (EMA correctness, REAL units bug that fakes termination via wrong tau): `alpha_fb = dt/tau_fb_ms` is the wrong EMA coefficient and silently mis-scales the filter

The design writes "EMA `alpha_fb=dt/tau_fb_ms`." The exact discretization of a first-order low-pass `dr/dt = (x - r)/tau` over a step `dt` is `alpha = 1 - exp(-dt/tau)`, which the engine ALREADY uses everywhere: `decay_sE = np.exp(-dt/tau_r_AMPA)` (line 120), `ee_std_recover_factor = 1 - exp(-dt/tau_ms)` (line 64), `ou_a = exp(-dt/tau_n)` (line 149). `alpha = dt/tau` is only the first-order Taylor approximation, valid when `dt << tau`. With Abbott seconds-scale tau (2000 ms) and dt=0.05 ms, `dt/tau = 2.5e-5` vs `1-exp(-2.5e-5) ≈ 2.5e-5` — the approximation is fine at tau=2000. BUT the design's own pilot/grid includes shorter tau, and the faithful-abbott rung mentioned tau in the hundreds-of-ms range; the robustness rung brackets {500,2000,8000}. At any tau where the approximation drifts you get a filter whose effective time constant is NOT what the grid axis label says — so the "tau too slow to terminate sub-second event" diagnosis (the design's risk #3) becomes uninterpretable because the axis is mislabeled. A mis-scaled filter that integrates faster than its nominal tau can manufacture a "termination" that you then mis-attribute to a tau you never actually ran.

**Fix:** Use `alpha_fb = 1.0 - np.exp(-dt / tau_fb_ms)`, matching the engine's own OU/STD/synaptic convention verbatim. Never `dt/tau`. This also makes the A1c filter visually consistent with the documented `ee_std_recover_factor` so a reviewer recognizes the pattern.

Completion-vs-timeout is a compute artifact, not a physiological readout.

## HOLE 6 (artifact masquerade, REAL): the `_state` classifier can flip runaway→"silent" with ZERO real event, faking the "high gain → silent" dose-response rung

`_state` (lines 73–79): `silent` is returned when `gr = global_E_rate_mean_hz < 0.3`. The design's PASS condition (4) requires "highest gain → silent" as the protective end of the dose-response. But `silent` here means near-zero global rate — which is ALSO what you get if feedback is so strong the kick never ignites anything (or if the spontaneous core never fires). So "high gain → silent" is satisfied identically by "Abbott global inhibition shut down a real seizure" and by "feedback clamped the network so hard nothing ever happened." Those are opposite scientific claims with the same label. The design half-notices this (risk #2, "over-suppression masquerading as termination") but only guards the *intermediate* rung ("event-still-peaks-high AND I_global rises during event"); it leaves the silent rung unguarded, so the dose-response monotonicity (runaway→seizure→silent) can be manufactured by a brake that never allows an event at any gain ≥ some threshold.

**Fix:** Require that the silent rung be reached *through* a self-terminating rung as gain increases at FIXED tau — i.e. there must exist an intermediate gain where an event provably ignites (peak `active_E_fraction` in the seizure band, `gr ≥ 0.3`) AND terminates, before the silent rung. If raising gain takes you runaway→silent with NO intervening ignite-then-terminate cell, that is the design's own FALSIFIED condition ("runaway jumps straight to silent") and must be reported as such, not smoothed into a monotone dose-response. Also: in the silent rung, check `active_E_fraction_peak` — if it never crossed the event bar at ANY point, label it "suppressed (no ignition)" distinct from "terminated," so the figure can't read a never-ignited clamp as the protective end of an Abbott curve.

## HOLE 7 (artifact masquerade, SECONDARY): `prefix_peak` calibration window may sit on top of the spontaneous core's own firing, biasing the bar

The design correctly mandates `--event-bar-mode prefix_peak` (length-stable, good — avoids the record_peak late-event-raises-the-bar artifact). But `prefix_peak` calibrates the event bar from the first `--cal-prefix-ms` (default 3000ms, line 456). The substrate is the **twoend_equal spontaneous core** which fires on its OWN without a kick (kick is disabled here: `t_kick=1e9` at line 590). This interacts with Hole 5/6.

**Fix:** Cross-check, as the design's `event_bar_discipline` already half-says, by reading termination from the **raw `rate_E` sustained-below-baseline** (a baseline computed from `BASELINE_MS`, line 597, which the runner already has), NOT from the prefix-calibrated active-fraction bar alone. Make the raw-rate sustained-return the PRIMARY termination criterion and the active-fraction bar a secondary confirmation, so a spontaneously-contaminated prefix window can't drive the verdict. Optionally widen/validate the prefix window contains no event before trusting it (the runner has `active_E_fraction_peak` to check).

Then sanity-calibrate `gain` so that at the A1b seizure-like rate (`global ≈ few Hz`) `I_fb` is comparable to the *static* `global_ei_scale` increment that already converts seizure_like→interictal (≈ the 1.0→1.3 step). Without that calibration anchor the gain rungs are guesses and the pilot can read "all silent" or "no effect" purely from a units error, masquerading as "Abbott falsified."

## HOLE 4 (artifact that fakes termination) — `_state` reads `r95_mm` which only exists with `--dump-fullfield`; `seizure_like` is structurally unreachable without it

`_state()` (line 77): `seizure_like` requires `coll>0.3 AND r95>8.0`. `r95` comes from `_fullfield()` reading `fullfield_{tag}.json`, which is only written when the runner is invoked with `--dump-fullfield` (runner line 665). If A1c's grid driver omits that flag, `r95=None→0`, and **every terminating run collapses to `interictal_like`** (never `seizure_like`). The design's PASS clause (2) demands the intermediate gain "flips to seizure_like/interictal_like" — the `/interictal_like` escape hatch means a run that *over-suppresses* the event into a small axial blip reads `interictal_like` and counts as PASS. That is over-suppression masquerading as Abbott termination — exactly the artifact the design's own risk (2) says to guard against, but the guard ("event-still-peaks-high") is not wired to `r95`/`seizure_like`.

**FIX:** Mandate `--dump-fullfield` in the A1c grid (so `r95` and `seizure_like` are reachable), and make the PASS require the terminating run to be `seizure_like` (large event that returns), NOT `interictal_like`. An event that shrinks to interictal-scale before returning is suppression, not "a seizure the feedback shut down." Add `r95_at_termination` and `active_E_fraction_peak` to the hard PASS gate, not just `return_fraction`.

## HOLE 5 (artifact that fakes termination) — `collision_rate_returned_sidecar` requires the two-focus sidecar; it is NaN unless `twoend_equal` with 2 cores AND events `returned`

`build_sidecar` only fires when `len(core_masks)==2` (runner line 809). The `seizure_like` clause needs `coll>0.3`. But the sidecar's `collision_rate` is computed **only over RETURNED events** (runner comment line 806). On a runaway gain=0 run, few/no events "return," so `n_sidecar≈0 → coll=None → _state` can't ever reach `seizure_like` and falls to the `runaway`/`silent` branches. The collision metric is therefore **only defined on the very runs where the event already self-terminated** — it can never be the evidence that *distinguishes* a terminated event from a runaway one, because it doesn't exist on the runaway side. The design lists `collision` in PASS clause (2) as if it's a discriminator; it's a post-hoc descriptor of already-returned events.

**FIX:** Do not use `collision_rate` as a termination discriminator. Demote it to a descriptive sidecar (as A1b does). The PASS discriminator must be the raw `rate_E(t)` sustained-below-baseline crossing (`T_terminate`) plus `r95`/peak, all of which are defined on both runaway and terminating runs.

## HOLE 6 (the bit-parity claim has a real subtlety the synthesis half-acknowledges) — but the regression test as specified can still pass while parity is broken

The minimal-engine short-circuit (`if i_global==0.0: I_net=I_E-I_I`) is correct and necessary (subtracting a zero *array* is not guaranteed bit-identical, and even the scalar `0.0` path changes the float-op graph). But two gaps remain:

1. The design's regression is "full-trace `np.array_equal` at gain=0." `np.array_equal` returns **True for two NaN-free identical arrays but also silently treats `-0.0 == 0.0` as equal and does not catch a changed RNG consumption pattern that happens to land on identical rates**. The real parity risk in this engine is **RNG-stream drift**: if the EMA or the I_global path draws *any* `rng` call (it shouldn't, but the design must assert it), every downstream `rng.poisson`/`standard_normal` shifts and the trace diverges. The M1 precedent (line 172-178) explicitly says "no new RNG draws." The design must add: **assert the gain=0 path makes zero `rng` calls** (e.g. compare `rng.bit_generator.state` before/after, or reuse the existing `verify_pre_kick_identical` discipline across the FULL trace, not just pre-kick).
2. `np.array_equal` on `rate_E` (counts) is coarser than on `V`/`I_E`. Parity must be asserted on a **continuous** recorder (e.g. `lfp_trace` or a dumped `V` snapshot), because two different membrane trajectories can produce the same integer spike count per bin. The design says "full-trace array_equal" but names `rate_E`-style readouts; counts can mask a sub-threshold-V divergence that only manifests at a later seed/parameter.

**FIX:** Regression = (a) `rng.bit_generator.state` identical after a gain=0 vs a pre-A1c run, AND (b) `np.array_equal` on a continuous recorder (`lfp_trace` with a fixed LFPRecorder, or an added debug `V`-dump), not just `rate_E`. Then re-bless. Also: with **59 call sites** across 40 files, the new kwargs MUST default to `feedback_gain=0.0, feedback_tau_ms=0.0` AND the short-circuit must trigger on `feedback_gain==0.0` (the master knob), because `feedback_tau_ms` will be 0.0 at the default and a `dt/0.0` EMA alpha would NaN — confirm the short-circuit is gated on gain, never on tau.

## HOLE 7 (a noise/detector artifact CAN masquerade as termination) — `T_terminate` "drops below 1.5×baseline and STAYS" is gameable by the EMA's own lag + finite-size noise

The design defines `T_terminate` via the `compute_metrics` baseline (50–150ms window) and "sustained below." Two artifacts:

1. **The EMA lag is the very thing being measured.** A slow `tau_fb=8000ms` brake (one of the rungs) cannot rise within a sub-second event, so it can't terminate that event — but if the event happens to self-limit on its OWN (the substrate is the Stage-3 core which *already self-terminates at baseline*, per the A1b `interictal_like` cells), `T_terminate` reads finite and the design credits the feedback. **You cannot distinguish "feedback terminated it" from "it self-terminated and the slow feedback was a bystander"** without a no-feedback control on the *same seed/corner*. The design has the gain=0 control, but PASS clause (3) ("I_global RISES during the event and the event ends while E_bar is high") is the only stated guard — and a slow-tau EMA rising on the event's own decay tail trivially satisfies "rises during the event" while contributing nothing.
2. **Finite-size / single-realization** (the exact burn the prior SNN work flagged, per MEMORY): a single seed's runaway can stochastically self-quench. The design requires 3-seed sign-consistency — good — but `T_terminate`'s "STAYS below for a sustained window" threshold is not specified as a fraction of T, so a brief dip in a still-runaway trace can read as termination. The A1b runner already had to add `prefix_peak` precisely because `record_peak` let late events reshape the bar; the design adopts `prefix_peak` (good) but `T_terminate` is computed off `rate_E` raw, not the bar-calibrated `af`, so it inherits none of that protection.

**FIX:** (a) Add a **gain>0 with tau=∞ (or a frozen-EMA) control** OR require the causal test: I_global must rise *before* `rate_E` starts falling (cross-correlation lead, not just "rises during"). A bystander slow EMA rises *after* the peak; a causal brake rises *before* the decay. Make "I_global leads the rate decay" the PASS discriminator, replacing the weak "rises during the event." (b) Define `T_terminate` as sustained-below for ≥ a fixed ms window (e.g. ≥500ms, or ≥3·tau_membrane) AND require it on the bar-calibrated `af`/`tonic_fraction`, reusing `_state`'s `tonic>0.4` runaway clause as the verbatim "still going" check rather than a hand-rolled raw-rate threshold.

---

## Net verdict on this axis

The design's parity discipline is mostly sound (HOLE 6 is a tightening, not a break). But the **termination claim itself is not yet testable as specified**: the named baseline corners have no measured readouts (HOLE 1), the runaway being "terminated" is two different mechanisms only one of which Abbott's global feedback can see (HOLE 2), the EMA's injected magnitude is dimensionally unpinned so the whole sweep can read null/silent from a units error (HOLE 3), and three of the PASS-clause discriminators (`seizure_like`, `collision`, "rises during event") are either structurally unreachable without flags or satisfiable by a bystander slow EMA (HOLES 4, 5, 7). A run could come back labeled "Abbott termination PASS" while actually showing *static-equivalent over-suppression of a self-terminating substrate*.

**Minimum repair to make a PASS meaningful:** (1) re-anchor on `l2_g1.0` measured runaway + keep `g0.7` only as completed-with-readout secondary; (2) stratify by core-vs-global runaway type; (3) pin EMA = intensive Hz with a calibration anchor to the static `global_ei_scale` step that already converts seizure_like→interictal; (4) mandate `--dump-fullfield`, require terminating run = `seizure_like` (not `interictal_like`); (5) replace "I_global rises during event" with "I_global *leads* the rate decay" as the dynamic-vs-static discriminator; (6) regression on `rng.bit_generator.state` + a continuous recorder, not just `rate_E`.
