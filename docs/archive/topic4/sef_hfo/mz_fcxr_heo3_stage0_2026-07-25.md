# FCXR-HEO3 Stage H3.0 — 联合滑窗 + source-space 审计（HEO2.1 review P1-b/P1-c 收口）

**日期**: 2026-07-25 ｜ **分支**: `codex/topic4-mz-fcxr-heo1` ｜ **性质**: HEO3 第一阶段审计（compute-free 重分析 + 1 次复跑），**非**因果实验。

**判决**：① **两个仪器 bug 先修**——250 ms 联合窗在物理上量不了本目标（1–4 Hz 无频率格点 + 16 Hz 泄漏进 8–13 Hz 假造"宽带"），瞬时相位对齐度（Kuramoto R）问错了问题（行波被误判成"去同步"）；改用 **1 s 窗 / 100 ms 步进 + 活动样本上的成对锁相值（PLV）**。② 修正后 **8 个 arm 无一拿到哪怕一个联合目标窗（0/8，最长连续 0 ms）**。③ **订正 HEO2.1 主张**：快 τ/10% 的"去同步"大半是开—关切换假象（爆发内 PLV 0.86 vs 参照 0.95，仅 10% 窗低于阈值），**拓宽是真的**（宽带窗 32% vs 参照 2%）；且**拓宽与去同步在时间上错开**——宽带峰值出现在 PLV **最高**时，PLV 只在状态崩塌时下降。④ **source-space 反驳"一个核很响"**：参与比 ≈0.60（约六成 E 细胞承载活动）、轴外触点 111 Hz，sensor 15/15 有真实组织招募支撑；但**没有持续的区域交替**（质心轴坐标参照跨度 0.005、前体去掉崩塌窗后 0.144）。

## 摘要（朴素话）

**测了什么** — 上一轮我们说"快适应把那个 16 Hz 的整片同步态部分地拉宽了、也部分打散了同步"。但那两句话是把整段 4 秒各自平均出来的：**拉宽的时刻和打散的时刻可能根本不是同一时刻**，而且一个一阵一阵开开关关的信号，"平均同步度"本来就会掉——那是开关造成的，不是同一阵放电内部真的乱了。所以这一步只做一件事：把四个要求（多少电极参与、频谱是不是真宽带、放电彼此还同不同步、能量够不够高）放到**同一个时间窗里**逐窗判，看它们能不能**同时**成立、能连续维持多久。另外还要回答一个更基础的问题：十五个电极都亮，会不会只是**同一个很响的小核**被十五个电极同时看到？

**怎么测的** — 先踩了两个坑，都修了。第一，我按 review 要求用 250 ms 的窗，结果跑出"宽带 99%、目标 98.7%"这种好得离谱的数——查下去发现 **250 ms 的频谱最低格点就在 4 Hz，1–4 Hz 那段根本没有数据**；而且这么短的窗"分辨力"很粗，那个很强的 16 Hz 峰**直接漏到 8–13 Hz 上抬了 20 分贝**，于是"五个频段里有三个抬起来"被泄漏自己满足了。目标表型是靠约 3 Hz 的慢成分定义的，250 ms 连一个 3 Hz 的周期都装不下，所以**最短只能用 1 秒的窗**（约 3 个周期），靠 100 毫秒挪一步来保证判定够密。第二，我一开始用"所有电极是不是同时到波峰"来量同步——但这块组织的 16 Hz 参照态是一列**行波**：相位沿电极一路错开约 186 度，彼此关系稳得很（组织得极好），可"同时到峰"的程度只有 0.43，**会被误判成已经打散了**。所以换成"**在放电的时候，电极两两之间的相位关系稳不稳定**"——行波的关系是稳的（读数接近 1），只有关系真的乱掉才降下来；一段死寂则判为"看不出来"，不许算作"打散"。至于第二个基础问题，我们直接回到组织里数细胞：把细胞按源核、汇核、两核之间的走廊、走廊之外分成四片，看每片放电多少、多少比例的细胞真正在承载活动、活动的重心在不在沿轴移动。

**揭示了什么** — 四个要求**从来没有在同一个时间窗里同时成立过**（八个实验条件全是 0）。而且看清了一件上一轮被平均值藏住的事：**这块组织是在"相位还锁着"的时候把频谱拉宽的，它真正打散同步只发生在活动正在熄灭的时候**。换句话说，快适应给的不是"又宽又散又持续"，而是"锁着相地宽一下，然后散着死掉"。另一边，"十五个电极只是看同一个核"的担心可以排除：真的有约六成细胞在承载活动，连离轴最远那片也在以每秒一百多次的频率放电，只是从核区到轴外有大约四倍的梯度。但**也没有看到区域轮流承载活动**——活动重心基本钉在轴的中点附近不动（唯一一次大幅移动，正好就是活动几乎熄灭的那一瞬间，此时只剩不到一成的细胞还在放）。这恰好把下一步要造的东西说清楚了：需要一种**能在不杀死状态的前提下把相位关系打乱、并让不同区域轮流承载**的机制。

（内部归档代号：HEO3 H3.0；`joint_target_windows` 判据 recruit≥12 ∧ broadband≥8 ∧ PLV≤0.60 ∧ rate≥60 Hz；窗 1000 ms / hop 100 ms；`pairwise_plv_windows` active-gated；`source_space_audit` 分区 core_source/core_sink/axis_corridor/off_axis + `participation_ratio` + centroid axis coord。）

## §1 两个仪器订正（在报任何数字之前）

### §1.1 250 ms 联合窗物理上不可用 → 1 s / 100 ms
review 要求 200–300 ms 联合窗。实测该窗长对本目标 **mis-specified**：

| 同一段 m_off 信号 | 1–4 Hz | 4–8 | 8–13 | 13–30 |
|---|---|---|---|---|
| 1 s 窗 ΔdB | −23.1 | −15.3 | **−9.8** | +15.8 |
| 250 ms 窗 ΔdB | **−inf（无格点）** | −11.4 | **+10.0（泄漏）** | +14.9 |

250 ms 窗第一个频率格点在 4 Hz（1–4 Hz 段为空），汉宁窗主瓣约 16 Hz 宽 → 16 Hz 主峰泄漏进 8–13 Hz 抬 +20 dB。首次运行因此报出 **虚假的"宽带 99%、联合目标 98.7%"**。目标表型由 ~3 Hz 内容定义 → **1 s 是能守住目标定义的最短窗**（3 Hz 的 3 个周期、~1 Hz 分辨），判定密度由 100 ms hop 保证。已写入 `band_power_windows` docstring + 回归测试 `test_short_window_leaks_and_empties_low_bands_so_gate_must_not_use_250ms`。

### §1.2 相位指标问错问题（CLAUDE.md §6.1）→ 成对 PLV
瞬时相位对齐度（Kuramoto R）问"是否同时到峰"；本假设问"相位**关系**是否还稳定"。16 Hz 参照态是**行波**：coherence 0.98、phase span 186°，但 **R=0.43** → 会被判成"已去同步"（错误原因）。改用 **活动样本上的成对 PLV**（对固定滞后不敏感 → 行波读数 ~0.95 = 组织完好；关系漂移才下降）。静默窗返回 nan（判为"看不出来"，**不得**算作去同步）。回归测试：`test_order_parameter_traveling_wave_looks_dispersed_but_is_organized`、`test_pairwise_plv_is_undefined_not_low_when_window_is_silent`。

## §4 这一步为 H3.1 锁住了什么

1. **地板 = 0**：任何 HEO3 arm 只要拿到 >0 的联合目标窗且最长连续 >0，就是相对当前的严格改进。主判据 = **联合目标窗占比 + 最长连续时长**（后者是"持住"的度量）。
2. **稀缺判据 = 去同步**（前体仅 10% 窗），不是招募（81–100%），也不是宽带（32%）。
3. **要造的东西被精确定义**：**在不杀死状态的前提下打乱相位关系**（当前只有"锁相地宽"或"散着死"两种）。这正是"空间组织化的恢复时间差让区域交替承载"要干的事 → HEO3 2×2 的假设方向是对准的。
4. **⚠️ 对 review §4 一句的微调**："均匀适应本身已经去同步"这一论据**变弱**（真实的爆发内去同步很有限：PLV 0.86 vs 0.95）。但这**不**反过来证明空间异质是必需的——那正是 H3.1 要做的因果检验。措辞仍守 §7.5：**不可声称"宽带必须来自空间去同步"**。

## §5 边界

- 本阶段是**审计/重分析**，不是因果实验；单 seed（seed1）、单锚点。
- 判据阈值（recruit≥12、broadband≥8、PLV≤0.60、rate≥60 Hz）为 H3.0 **暂定门**，H3.1 前应按真实 E1146 目标再核一次（当前 0/8 不因阈值松紧而翻转：前体四项分别 81/32/10/48%，任何合理阈值都不会让它们共存）。
- source-space 分区是**几何定义**（核半径 1.5、走廊宽 = 核半径），非功能定义。
- 质心为**率加权重心**，对双侧同时活动不敏感（两端同时亮 → 重心仍在中点）；"区域交替"在 H3.1 应另加**分区活动的反相关**判据，不能只看重心。
