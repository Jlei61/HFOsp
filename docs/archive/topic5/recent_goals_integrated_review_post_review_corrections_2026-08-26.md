## 1. P0：H2b 的承重数字取自已被覆盖的旧文档

### 揭示了什么

报告说"27 人 361 次发作主读出 +0.446 SD，20/27 同向，p=0.019"。这组数字来自
2026-08-20 的 markdown。磁盘上的产物是 2026-08-21 01:50 重跑的，比那份文档新，
数值不同。我直接从逐发作产生表
（`preictal_effects__linear_graph_recurrent__lead30m.csv`）重算，复现了磁盘产物：

| 量 | 报告写的 | 实际（重算复现） |
|---|---:|---:|
| 主层中位偏移 | +0.446 SD | **+0.4582 SD** |
| 同向患者 | 20/27 | **21/27** |
| 符号检验 p | 0.019 | **0.00592** |
| 主层背后的发作数 | 361 | **339** |
| 高可观测层中位 | +0.288 | **+0.2667** |
| 高可观测层同向 | 18/27 | **17/27** |
| 高可观测层 p | ≈0.12 | **0.2478** |
| 高可观测层发作数 | 203 | **201** |

另外，**361 和 203 是"可分析"和"前提满足"的行数，不是进入读数的发作数**。
22 次发作的伪起点零分布退化、算不出标准化偏移，所以主层真正用到的是 339 次
（高可观测层 201 次）。把资格分母写成读数分母属于分母虚高。

方向上：主层其实比报告写的更强（p 从 0.019 到 0.0059），高可观测层比报告写的更弱
（p 从 0.12 到 0.248）。**定性结论不变**：主层有探索性偏移，高可观测层不成立。

报告自己写了"优先级规则：机器审计和后出的 corrections 高于早期 report"，这一段
违反了它自己的规则，"承重数字已与机器 JSON 交叉核对通过"对 H2b 不成立。

## 2. P0：H3 资格闸门按错误的时间分区计数，下一步就会发作

### 测了什么

"这位患者有没有足够多互不重叠的完整长窗口"——这是本轮把 H3 判为"未运行"而不是
"阴性"的那把尺子。

### 怎么测的 / 错在哪

尺子（`run_r1_3_long_h3_followup_queue.py::support_for`）按 `event_session` 分组数窗口；
但真正建窗口的代码（`build_long_window_design`）按**记录覆盖段**分组。
session 是一个跨越普通记录间隙仍然延续的标签，比覆盖段**粗**：

| 患者 | 覆盖段 | session | 差异 |
|---|---:|---:|---|
| epilepsiae_922 | 49 | 11 | 是 |
| epilepsiae_958 | 135 | 9 | 是 |
| epilepsiae_620 | 64 | 9 | 是 |
| 三位 Yuquan 分诊患者 | 1 | 1 | 否 |

于是尺子把"跨过没记录的时间"的窗口也算了进去。实测资格判定翻转：

| 患者 | N | session 口径 | 覆盖段口径（真实设计） |
|---|---:|---|---|
| epilepsiae_958 | 1000 | 41/15 合格 | **2/0，且只有 738 个窗口** |
| epilepsiae_958 | 2000–5000 | 27/10 … 12/5 合格 | **0 个窗口** |
| epilepsiae_922 | 3000 | 16/5 合格 | 4/2 不合格 |
| epilepsiae_922 | 4000 | 12/4 合格 | **0/2，1,749 个窗口** |
| epilepsiae_922 | 5000 | 9/4 合格 | **0/1，204 个窗口** |

`chosen` 取的是"合格里 N 最大的那个"，所以按旧口径 922 会被安排在 **N=5000** 上跑，
而那个尺度的真实设计只有 204 个窗口、TRAIN 侧一个互不重叠的完整窗都没有。

### 为什么这次没出错、下一步会出错

本轮分诊的三位患者（韩宇轩、陈子阳、程帅）都是 1 段 = 1 session，所以结论不受影响。
但报告 §11.1 把 **`epilepsiae_922`** 列为下一优先患者——闸门会在下一步立刻发作。

**已改**：`support_for` 改为按覆盖段分区，并在产物里同时记录段数与 session 数。
按覆盖段，922 在 **N=1000（21/7）和 N=2000（10/3）** 仍然合格；620 在**任何 N 上
一个窗口都没有**；958 只在 N=1000 有 2/0，不合格。

## 3. P0：超长尺度的两个"主读数"里，六小时那一档不是失败的检验，是发散的拟合

### 揭示了什么

每一条拟合臂都**内含**截距对照臂那个常数，所以在 validation 上它最差也只该落在
截距对照附近。实测 70 条已归档的超长臂里有 **26 条**落在截距对照的 4 倍以上，
最极端的是 **6,809 倍**。按组看：

| kernel / 患者 / 窗口 | 非可估计 / 总数 |
|---|---:|
| boxcar / 韩宇轩 / 6 h | **7/7** |
| boxcar / 韩宇轩 / N=2000 | 0/7 |
| generator / 韩宇轩 / N=2000 | 6/6 |
| generator / 韩宇轩 / 6 h | 7/7 |
| boxcar / 陈子阳 / 三档 | 0/7 各档 |

所以报告 §7.4 表里的 **`6 h boxcar：real−intercept = +94.9233，0/7 有利`**
不能读成"两个主对照均失败"——**它 7/7 都不是有效估计**，与 T2-S1 的结构零同类，
应写为不可估计。**`N=2000 boxcar：+4.1003，1/7`** 是真实估计，那一行的判读不变。

### 机制

`_solve_ridge` 用的是绝对惩罚 `ridge × I`，而 Gram 矩阵随窗口数 × 读出行数增长，
所以整个网格 `{1e-4,…,100}` 实际上等于"不做正则化"：**76 条归档拟合里 47 条把
ridge 选在网格上界**。同时 TRAIN→validation 的目标分布位移极大（`no_edge` 相对
截距对照的中位倍数 42.9、最大 8,992），无正则化的 16 参数拟合就外推爆掉了。

**已改**：惩罚改为按 Gram 对角均值缩放（尺度无关），网格扩到 `1e-8…1e4`，
并记录是否选在边界；新增 `estimability_guard`（臂 > 4×截距即判不可估计）与
`target_shift_audit`（TRAIN→validation 目标位移）。已加单元测试锁住
"选择结果不随算子缩放改变"。

## 4. P1：超长尺度的"独立窗口数"对 boxcar 用错了分母

`endpoint_support_audit` 用生成器最慢模态（54 分钟）当去相关长度。对 boxcar 而言
去相关长度是**整个窗口**。改正后：

| 患者 / 窗口 | 报告里的有效独立 validation 窗 | boxcar 正确口径 |
|---|---:|---:|
| 韩宇轩 / N=2000 | 5.22 | **0.48** |
| 韩宇轩 / 6 h | 5.22 | **0.79** |
| 陈子阳 / N=4000 | 6.17 | **0.91** |
| 陈子阳 / 6 h | 6.17 | **0.93** |

即高估 6–11 倍，而且正确值**不足 1 个**独立 validation 窗。这比报告写的
"validation 每条件 1 个独立窗"还要更紧。**已改**：该审计现在接受 `exposure_memory`
并对 boxcar 用窗口长度。

## 5. P1：延迟对照与真实臂共享大部分暴露

延迟固定 1000 次事件，而窗口是 2,000–15,000 次，所以延迟窗与真实窗重叠
`(N−1000)/N`：N=2000 时 50%，N=4000 时 75%，N=10000 时 90%。已归档超长臂的
**共享比例中位数为 0.667**。因此 `real − delayed` 在大 N 上几乎没有分辨力，
它的零值**不能**读成"载荷时序不重要"。**已改**：新增 `delayed_control_overlap`
并写入结果 JSON。

## 6. P1：`--t1-source r1_3` 的可用性闸门把一个条件重复算了两次

## 9. P1：H2b 仪器本身还有两处会把效应压向零 / 让基准不公平

- 伪起点的"避开发作"阶梯只用了**落在可分析事件跨度内**的发作，跨度外的发作
  不会把附近的伪时刻排除掉，于是真正的发作前时刻进了零分布，把效应压向零。
- 干扰变量基准 z 用 `pseudo_times[:60]`，而端点 z 用全部 200 个；伪起点是按匹配代价
  排序的，所以基准拿到的是**更紧的**零分布，|z| 被抬高，"状态必须赢过干扰变量"
  这个比较不成立。

两处均**已改代码**，但 12 个 H2b 产物是修复前跑的：**重跑前 §1 的更正数字仍是当前
最好的数字，重跑后需要再更新一次**。

## 10. 措辞

`intercept_operator` 返回 `dim` 个自由参数，真实臂是 `2×dim`（repertoire 源是 `3×dim`）。
所以它是**截距匹配**，不是"同容量"。超长报告里的"同容量截距"应改为"拟合截距对照"。
