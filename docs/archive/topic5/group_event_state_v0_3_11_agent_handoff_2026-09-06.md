## 5. 资源和失败处理

一 GPU 初始一任务，最大实际训练 shape 先跑完整训练步，实测峰值 ≤18GiB 后才入队，保留至少约 4GiB 余量。微批减半、有效 batch/权重不变、完整梯度；OOM 不允许改历史或目标来继续填同一张卡。

单元以 config/data/split/source 哈希定身份；跨进程文件锁，输出临时写后原子发布，恢复比对全部身份。完整保存优化器、LR 调度、CPU/CUDA/numpy/Python RNG 和 batch 位置。故意崩溃恢复须覆盖 LR 和阶段边界，配置变化必须拒绝复用。

每 30s 检查进程/显存/状态；有已合格待办且 5min 无训练才诊断并补位。静默正常监控，出现失败、关键判据变化、阶段完成或需交接时报告。没有科学上合格的 GPU 待办时记录原因；不做无关负载。

## 6. 必须能回答的验收问题

1. 所谓事件前状态是否真的排除了当前事件及尚未发布的输入？
2. 背景、固定历史、常数和状态是否都得到充分优化机会？
3. 非正结果的那个具体比较，有没有同新训练器、同测量、同端点的功效界限？
4. 改善是次数，还是条件触点/形态？是否属于 producer 从未训练过的目标？
5. “共享”是否来自同一患者同一 checkpoint，而不是跨患者/家族拼接？
6. 缺测是否与零事件混同？短期跟踪是否被叫作长时自主动力学？
7. 发作关联、回顾性跨簇、前推连续风险是否各用各的分母和语言？
8. 删除历史的效应是否又被偷换成 IED 生理反馈？

最终必须同时给机器执行状态和科学状态；不以卡数、GPU 满载或工程测试通过代替科学验收。未获阳性是允许的，沿着无判别力的线重复扩容不算完成任务。
