## 已确认的关键问题

1. **P1：通道顺序拟合不能代替实际空间传播方向。** 原 XY 重搜已经取消旧的“先两个模式、后 OOD”排序，主目标是全事件云距离，另留 support/order/lag/coverage；但方向只是间接进入。现加入在相同触点坐标上测量的有符号传播方向分布，正反模式的比例也进入目标，不调用 KMeans 或 OOD 删除事件。
2. **P1：结构轴与行为轴不能混称。** 当前结构核轴为 −22.805383965°，AR=2，适用于整个 E 群体的距离衰减连接规则。现有患者知情坐标注册仍是输入，不能因为固定该轴后拟合成功就称为独立发现患者轴。全片 source onset 的行为轴另外测量并保存，不拿 core 连线当传播方向。
3. **P1：两根电极轴的稀疏采样会产生不可估计方向。** 每个事件至少 4 个有效触点，中心化二维坐标条件数不超过 20；近共线、同步或不足触点的事件不硬造箭头，也不从分母删除。方向质量由平面拟合的 adjusted R² 加权，因此该读出仍是平面传播近似，不是任意弯曲行为场的恢复。
4. **P1：固定阈值生成参数并不等于每个位置得到完全相同的有限阈值样本。** 原 signed-depth 规则按神经元固定随机分位数，移动 core 会选中不同神经元。本轮不改变定义，逐网络保留实际 node_mapping；最终若要将差异归因于位置，需要预算和阈值实现的敏感性核查。

## 目标函数

由冻结训练合同中的 30,049 个事件、56 个记录块估计目标，不加载患者留出或发作数据。坐标来自原始 contact_shaft_contract，患者和模型严格校验触点名称、顺序和二维坐标一致。

拟合 `t = intercept + gx*x + gy*y`，`+g` 为早到晚。方向以 24 个圆周软分箱表示，保留正反向；每个事件将 adjusted R² 的质量分配给其方向，其余进入单独的“不可解析／非平面”项，总分母始终为所有返回事件。距离是有符号单位圆加独立未解析状态上的 Gaussian-kernel MMD；Gaussian 宽度固定为 0.5。

主目标：

`J = D_cloud / 0.1324583994 + D_direction / 0.2543820047`

两项尺度均在候选重评分前用患者训练数据固定：事件云尺度取 4 次事件内有限起始时间打乱的距离中位数，保持参与掩码；方向尺度取方向整体旋转 90° 的距离。没有用候选的得分范围反调权重。该归一化是训练数据扰动响应的尺度约定，并不表示两项对所有候选的贡献相同。

训练目标在同一坐标系下的加权主轴为 **−19.342543442°**，与固定 EE 轴相差 **3.462840523°**。29,301 个事件的空间回归可估计；相干方向质量为 0.4936804184，其余 0.5063195816 不可解释为“患者一半事件不传播”，只表示此平面方向摘要未分配出去的质量。32 次整记录块拆分距离中位数为 0.02686518，2.5–97.5 百分位为 0.00840479–0.05462112；90°旋转距离为 0.25438200，180°反向为 0.23833594。这些是读出灵敏度检查，不是模型的拟合结果或显著性检验。

主目标 core 先验权重为 0。另保存 `J + lambda*sin(core连线角−训练行为轴角)^2`，`lambda = 0.05, 0.1, 0.2` 的敏感性排序；0.1 作为预先指定的弱先验提名。它不规定 core 必须在两端、不规定中点、不限制四个 XY 坐标只能沿一条线变化。

## 并行与内存

新服务为 `codex-t4-xy-direction-20260905.service`，主入口 `scripts/run_topic4_xy_direction_research.py`。上限 24 个 worker，首次实际放行 20 个，原来为 11 个。数值线程限制为 1；每个 Python 进程仍可能显示额外运行时线程。

调度按 `/proc/meminfo` 的 MemAvailable 放行，保留 **40 GiB**；还扣除所有在跑任务未来可能长到预算峰值、尚未成为 RSS 的内存。8 s 阶段的单 worker 起始预算为 **10 GiB**，12 s 为 15 GiB，20 s 为 25 GiB；预算可按观察到的 VmPeak 的 1.5 倍向上增加。每个新 worker 用 `prlimit --as` 设置相同大小的地址空间硬上限，实际核查了新 worker 的 `/proc/<pid>/limits` 为 10,737,418,240 bytes。

地址空间上限是防止单进程无限增长的保护，不是给任务预分配内存；超过上限可能以分配失败结束。worker 失败或磁盘余量低于 30 GiB 时停止派发，已运行任务自然收尾，保留可重启的产物和日志。其他任务突发占用仍属于共享机器的不确定性，不能承诺任何外部负载下绝无 OOM。

资源轨迹保存在每阶段 `worker_resources_v2.json`；实时 `status.json` 记录活动 PID、预算、观测峰值、可用内存、完成数量与失败原因。控制器和新增评分代码另有 `runtime_lock_direction_v2.json`，原 worker 的全源码锁不变。
