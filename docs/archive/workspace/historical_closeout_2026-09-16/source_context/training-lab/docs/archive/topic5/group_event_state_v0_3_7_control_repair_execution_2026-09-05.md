# Group-Event State v0.3.7 控制臂修复与重跑合同

**日期：** 2026-09-05  
**状态：** `REPAIR_VERIFIED_FORMAL_EXECUTION_COMPLETE`

## 一句话

第一轮的人体跨臂数字作废，不是因为新 CT-DSSM 的连续时间实现错误，而是因为透明对照、最底层 rate 地基和多数 H2a 调制接口没有获得可比较的优化。修复后的正式重跑必须从全新结果根开始，并在控制臂与模型臂通过同一训练充分性闸门后才允许读取 SELECTION。控制配方必须先冻结，状态配方搜索随后全部在这条同一控制地基上运行；事后再把控制配方拼回已经完成的状态搜索不等价。

## 已确认的故障

1. 透明 `B_mark` 在第一轮 4/5 患者的保存权重严格为零；原 optimizer queue 没有调度新定义的 48 个 baseline recipe 单元。
2. 正式 dual 模型原本没有继承 baseline sweep 选出的初始化、warm-up 与 weight decay。
3. 最内层 `B_rate` 只检查是否离开初始点和是否顶预算，没有检查 INNER loss 是否实际改善。
4. H2a 三位患者的旧接口停在零；修复后保持 decoder parity，但从第二步起通路必须有梯度，并记录训练期最大调制幅度。
5. 8 h 的五分钟重叠行不是独立样本；卡片必须并报互不重叠的物理窗口数。
6. 32 h 固定模式长于当前 24–31 h 的评分段，主人体 bank 截至 16 h；32 h 只作留出跨度充分时的探索性敏感性。
7. 每张正式卡必须携带生成源码哈希；汇总不得用新代码解释旧卡。
8. “预算触顶”按训练是否因 `max_steps` 耗尽而结束判定，不按最佳 checkpoint 是否恰好位于最后一步判定；后者会漏掉“最佳点在 775、训练到 900 仍未满足 patience”这类真实预算截断。

## 放行规则

最终规则把“仪器是否真的被优化”与“人体是否出现增量”分开：

- 训练充分性只检查第一步梯度非零、训练期参数确实移动、且预算耗尽比例不超过 25%；
- `gain_over_parent`、非父 checkpoint 比例和患者间一致性单列为人体科学结果，不再拿它们定义模型能否训练；
- 每个新增臂仍必须显式保留已经拟合的父臂，因而正式评分时只能胜过或回退到父臂，不能靠随机初始化制造伪增益；
- 控制臂的合格性按患者先裁决，再聚合到队列，不能用全队列平均掩盖某位患者的地基耗尽。

任一承重家族没有梯度、没有参数移动或普遍耗尽预算，监督器停在 `STOPPED_AT_TRAINABILITY_GATE`。人体无增量本身不再触发工程停止；它进入正式 H1/H2，作为科学阴性或不可区分结果报告。H3 始终使用独立 `Z_phys` M0/M1/M2 生成模型，不把 observer update 当成生理反馈。

搜索严格分两阶段：先完成 48 个控制单元并冻结唯一 baseline recipe；再运行 264 个 `S_event/S_grid/S_dual` 单元。第二阶段每张卡必须记录同一个 `frozen_baseline_recipe`，否则汇总器拒绝出数。

# 2026-09-05 二次复核：嵌套父臂必须显式保留

第一版控制修复虽然给 B_mark 增加了学习率、预热和预算搜索，但把“相对随机小初始化的改善”当成了 B_mark 的增益。真实卡片显示，部分患者的 B_mark 能从随机扰动起点改善，却仍比已经拟合好的 B_rate 更差。因此该轮 `repaired_v3` 在控制搜索阶段暂停，未进入状态模型搜索，也未产生人体科学结果。

正式修复后，每个新增臂都显式保留父臂作为零增量候选：B_mark 的父臂是 B_rate；单流状态和随机状态的父臂是 B_mark；双流背景状态和事件状态也各自保留紧邻的已拟合父臂。非零初始化只负责启动梯度，不能再替代父臂进入科学比较。卡片同时区分：

- `parent_inner_loss`：真正的嵌套起点；
- `optimiser_initial_inner_loss`：优化器实际看到的随机起点；
- `gain_over_parent`：唯一允许解释为新增信息的增益；
- `first_step_gradient_norm` 与 `peak_parameter_delta_from_stage_start`：证明通路确实被探索；
- `training_budget_exhausted`：证明是否仍受训练预算限制。

真实患者 E1125 的修复烟雾卡给出：B_rate loss = 3.736047；B_mark 的随机优化起点 = 3.778152；训练后父臂仍胜出，B_mark gain over parent = 0；但第一步梯度 = 0.517、训练期参数最大移动 = 0.237、且没有耗尽预算。正确结论是“透明 mark 通路被充分探索，但这位患者当前没有 B_mark 增量”，而不是“基线没训练”或“B_mark 得到了正增益”。正式重跑使用全新 `repaired_v4` 根目录。

`repaired_v4` 完成 48 格控制搜索后又发现：B_rate 本身仍采用框架默认随机初始化，E1077 两个 seed 的起始 INNER loss 相差近 2，导致一个 seed 初始即最好、另一个 seed 可改善。该轮按闸门停止，未启动状态搜索。最终修复把 B_rate 的全部权重和偏置固定初始化为零；训练充分性由第一步梯度、训练期参数移动和预算是否耗尽判断，人体上的 rate gain 单独作为科学结果。B_mark 继续保留已拟合 B_rate 为父候选。下一轮使用全新 `repaired_v5` 根目录。

`repaired_v5` 完成 48 个控制单元和 264 个模型搜索单元后，event 与 grid 各有四个配方满足原闸门，dual 没有。逐卡复核显示 dual 并非训练失败：背景和事件通路都有非零第一步梯度、明显参数移动且没有预算耗尽；只是背景加入后，事件状态最多在 5/8 单元上产生 INNER 增益，低于原来的 6/8 效果阈值。把“人体是否出现队列级增益”写进“模型是否可训练”的闸门会把科学结果误报为工程失败。因此最终汇总将两者分开：`trainability_eligible` 只审计梯度、参数移动和预算；`inner_increment_supported` 单独记录非父选择比例和 INNER 增益。264 张卡的训练合同与数值仍有效，不因汇总语义修订而重跑。

正式 H1 运行期间又发现一个只影响报告、不影响已选配方的 P1：控制专用汇总已按患者正确拒绝 legacy 配方，但综合优化器汇总曾只按全队列平均重算，误把它标为 eligible。综合汇总现直接继承控制汇总的患者优先裁决，并增加回归测试；冻结选择始终是 `baseline_warm_init`，所以正式训练数值没有改变。

正式 H2a 运行期间又修正一处同类的报告标签问题：旧汇总器仍用“最终是否选择非零 checkpoint”代替“优化通路是否被探索”。修复后，训练性由第一步梯度、训练期间的参数/调制幅度实际移动以及预算是否耗尽判断；在通路确实移动后回退到父臂原点，应读作 INNER 不支持新增调制，而不是“接口没训练”。该修订只改变充分性标签，不改变任何人体 loss 或 contrast；新增回归测试覆盖“探索后选择原点”和“通路从未移动”两种情形。

主 H2a 60/60 完成后，joint sensitivity 原监督器只使用 1 worker/GPU，实测 GPU 利用率约 15%。为沿用已经通过主 H2a 的 4 workers/GPU 内存合同，完成监督器做了一次受控重挂：完整 card 均按存在性跳过，只把 joint 阶段提高到 8 workers。重挂时发现旧监督器在收到终止信号前又派出的两个孤儿进程；它们与新队列任务重复，已在写出 card 前终止。随后按 `(subject, seed)` 检查运行进程，重复数为 0；已经由旧监督器完整写出的 E253 seeds 20260903/20260904 保留，新监督器从其余 18 格继续。
