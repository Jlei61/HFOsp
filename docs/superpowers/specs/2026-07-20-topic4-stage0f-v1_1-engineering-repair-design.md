The complete v1 run is preserved unchanged at
`stage0f_smooth_transfer_variational_certificate_v1_hidden_gate_non_authoritative_2026-07-20/`.
Its execution lock and summary hashes are respectively
`3eb744cf436cabe4592b308aeca9dff630a3c644a95e70c32e62dc63e035eb06`

## 3. Same-map P and P2 closure

After shooting, apply the exact event-restarted Poincare implementation for two
returns. Every return is restarted from its linearly interpolated section state,
identical to the map used by shooting. Require both

\[
\|P(x_*)-x_*\|_{\infty,s}\le10^{-8},\qquad
\|P^2(x_*)-x_*\|_{\infty,s}\le10^{-8}.
\]

Both returns must satisfy the locked period band, upward crossing, transfer
support, natural bounds, finite values, and `<100 Hz` audit. The second crossing
of the non-restarted plotting trace is diagnostic only. Its phase-aligned
two-cycle residual remains subject to the unchanged `2e-4` gate.

## 4. Boundary-aware second-order RHS derivative

The two fixed scale-relative steps remain `[1e-5,3e-6]`, with absolute floor
`1e-9`. For every state coordinate and each step:

1. use second-order central difference if `x-h` and `x+h` are both inside the
   natural state domain;
2. otherwise use the second-order forward stencil
   `[-3 f(x)+4 f(x+h)-f(x+2h)]/(2h)` when both forward probes are valid;
3. otherwise use the symmetric second-order backward stencil when both backward
   probes are valid;
4. fail closed if no second-order stencil, including its `2h` point, exists.

Every probe must have finite RHS, positive divisor, and in-domain transfer
moments. Probe states are derivative evaluations, not physical histories; the
nominal trajectory alone carries occupancy and physical-state claims. Record
central/forward/backward counts for each step and time step. No first-order
fallback and no adaptive reduction of the two locked `h` values are allowed.

## 5. Nominal-map identity and event audit

For each time step, independently compute the nominal one-return map with the
shooting implementation and with the variational integrator. Before accepting
any derivative, require:

- period absolute difference `<=1e-9 ms`;
- scaled full crossing-state difference `<=1e-10`;
- identical section direction and no missing/extra crossing;
- all nominal states and moments finite and within natural/transfer support;
- no nominal `rE>=100 Hz`;
- both the continuous crossing RHS `dS_G/dt` and the discrete bracket slope
  `Delta S_G/dt` are positive and `>=1e-4 /ms`.

Report full nominal state and moment minima/maxima, the crossing fraction,
continuous and discrete transversality, and the complete physical/support audit.

## 7. Actual variational-trajectory transfer parity

The exact transfer audit uses 512 actual every-Euler states sampled uniformly
by index from each nominal variational return, not a reconstructed or unrelated
trajectory. For both E and I, compare cubic rate and derivatives with direct
log-domain Siegert quadrature. The v1 absolute/relative value and derivative
thresholds are unchanged. The complete two-point run must contain exactly
`2 points x 2 dt x 512 states x 2 populations = 4096` parity rows, each marked
`source=variational_nominal_euler_state`. This is a grouped schema gate, not
only a total-row gate: each `(alpha_G, dt, population)` group must contain
exactly 512 rows, `sample_index=0..511`, and 512 unique `source_state_index`
values. The four derivative rows must be the unique Cartesian product of two
points and two time steps.

The runtime rate path must evaluate only the spline value. Derivative spline
calls are restricted to the analytic Jacobian and parity audit; this is a
performance repair with exact value parity regression-tested.

## 9. Fail-closed execution and provenance order

The non-overwrite canonical result root is created only after all locked input
hashes, the source exact-transfer table, both Stage 0E point bundles, and all
v1.1 source hashes have been read successfully. A provenance or transfer-load
failure leaves that root absent so a repaired run is not blocked by an empty or
partial directory.

After successful preflight, point execution is fail closed. Any uncaught, or
lower-layer caught-and-reported, stencil, integration, whole-return probe,
exact-quadrature, or serialization exception changes the affected point to
`numerical_failure`, records its type/message/path, and prevents later locked
points from executing. A later point still receives the explicit outcome
`not_executed_due_to_engineering_failure`. Outer finalization must still write
two point outcomes, aggregate outcome JSON/CSV, a finalized execution lock,
the summary, `STATUS.md`, and a four-panel figure with explicit failure text.
A plotting fallback itself is evidence of failure, never a successful figure
gate. `execution_exception=false` is an explicit engineering-pass condition.

The execution lock covers the direct runtime dependencies used by the RHS and
atomic writers, including `src/sef_hfo_lif.py` and the Stage 0C transfer runner,
and records Python implementation/version plus NumPy and SciPy versions before
and after numerical execution.
