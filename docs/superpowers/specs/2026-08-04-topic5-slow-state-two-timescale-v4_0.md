# Topic 5 slow-state two-timescale interictal repertoire model v4.0

- **Status:** rev2 after design review; Phase 0–1 authorized; Phase 2 family selected by a
  frozen Phase 1 verdict, never by Phase 2 outcomes
- **Time step:** one **observation block** of `N_obs,p` consecutive events — the *smallest*
  window at which this patient's local repertoire rises above its own chance level
- **Primary scientific object:** a slow latent state that persists across many blocks and sets
  the distribution from which individual events are drawn
- **Primary question:** are a patient's tens of thousands of interictal events generated by a
  small number of long-dwelling latent propagation states, and can those states be identified
  within a patient from sparse SEEG?
- **Not a goal:** within-event next-rank prediction, single-event innovation, architecture
  search, proving a GRU is necessary, or using SNN / ictal / SOZ / geometry / A-B axis /
  old heldout20 as input or Gate
- **Output root:** `results/topic5_slow_state_two_timescale/v4_0/`

## 1. Frozen scientific question

Every earlier contract in this line made one event advance the model one step. That equates
an observation with a state transition. This contract separates them:

> An event is one observation emitted by a slow state. It is not one step of the slow state.

With `G_{0,p}` the patient's stable backbone and `z_b` the slow state of block `b`:

\[
x_e\sim p(x\mid z_{s(e)},G_{0,p}),
\qquad
z_{b+1}=F_p(z_b,\Delta t_b)+\epsilon_b .
\]

The tested chain is: stable backbone → a reliable local repertoire exists at some
patient-specific scale → that repertoire changes slowly and identifiably → states switch →
block composition precedes switching. Each arrow is a separate Phase; a later arrow may not
be claimed if an earlier one failed.

## 4. Data contract

### 4.1 Recording coverage comes from metadata, never from event density **[rev2]**

Source intervals are resolved from the frozen block inventories and, where those are absent,
EDF headers — **never** from the first and last detected event in a recording. A stretch of
normally recorded EEG in which no HFO event was detected is *recorded time with no events*,
not missing data, and rev1's event-density reconstruction would have mislabelled it.

The repository already implements exactly this and its docstring states the rule:
`build_source_segments` in `scripts/audit_topic5_event_innovation_v3_0_phase0.py`
("Resolve source intervals from inventories/EDF headers, never event density"). v4.0 extracts
that function into a shared module and reuses it. It must not be reimplemented.

A **session** is a maximal run of metadata source intervals whose consecutive
metadata gap is at most **300 s** and whose continuity group and montage hash agree. The
300 s threshold was chosen from the measured gap distribution before any v4.0 outcome was
computed; Phase 0 re-derives that distribution from metadata intervals and the threshold is
then frozen.

Two distinct quantities are recorded per session boundary and never conflated:

- `metadata_gap_seconds` — unrecorded wall time between two source intervals;
- `event_silence_seconds` — time between the last event of one session and the first of the
  next, which is always at least as large.

Every artifact carries `observed_events_during_gap = false`, meaning *no events were
observed*, never *no events occurred*.

### 4.2 Block

Three elapsed-time quantities are recorded per block and never conflated **[rev3]**:

- `transition_delta_t` — block centre to block centre. This is the elapsed time between two
  slow-state observations and is what the transition consumes.
- `inter_block_gap` — this block's first event minus the previous block's last event. It is
  close to an inter-block inter-event interval, not a state-to-state elapsed time. rev2 used
  this quantity for the transition, which was wrong.
- `metadata_gap_seconds` — unobserved wall time across a session boundary, from §4.1.

A **block** is `N_obs,p` consecutive events within one session. Blocks never span a session
boundary. A session's trailing remainder is dropped and counted, never padded. Every
individual event inside a block enters the likelihood; a block is never reduced to a mean
vector before the likelihood is formed.

### 4.3 State carry across gaps, with growing uncertainty **[rev2]**

The slow state carries **across** session boundaries. Carrying a deterministic hidden state
unchanged across a six-hour unobserved gap would assert knowledge the data does not contain,
so the transition is

\[
p\!\left(z_{b+1}\mid z_b,\Delta t_b,\text{gap unobserved}\right),
\]

whose **uncertainty grows with `Δt`**. For the semi-Markov family this additionally requires
marginalising over the unknown number of switches inside the gap rather than assuming none.

Analysis strata are fixed here:

- **primary** — block transitions **within** one continuous session;
- **secondary, reported separately** — block transitions that bridge a session gap.

A cross-gap result may never be pooled into the primary without being labelled.

### 4.4 Forbidden inputs

Old heldout20, ictal, SNN, SOZ, geometry and A-B axis labels never enter as input, target,
Gate or model-selection signal at any Phase. Time of day, event rate and recording identity
enter only as observation-layer nuisances (§9) and never as state labels.

## 6. Phase 1 — two scales, not one **[rev2]**

Phase 1 fits no state model.

### 6.1 The two scales are different quantities

\[
N_{\mathrm{obs},p}=\min\{N: R_{\mathrm{random}}(N)>q_{95}[R_{\mathrm{null}}(N)]\},
\]
\[
N_{\mathrm{break},p}=\min\{N>N_{\mathrm{obs},p}: R_{\mathrm{chrono}}(N)<R_{\mathrm{random}}(N)\}.
\]

`N_obs` is how many events are needed to see one local repertoire at all. `N_break` is where
a window starts averaging over a state change.

\[
\boxed{\text{model step size}=N_{\mathrm{obs},p}}
\]

**Not** the largest window below `N_break`. A state that truly persists for 500 events, cut
into 500-event blocks, leaves one block per state and no dwell for a semi-Markov model to
see. The step must be the finest legible resolution, not the coarsest tolerable one.

### 6.2 Descriptors: three primary, two secondary, ties from group identity **[rev2]**

Primary families, none of which requires a fitted model — an unstable template model would
corrupt the very scale estimate everything depends on:

1. contact participation rate;
2. participation-masked mean contact rank;
3. pairwise precedence probability.

Secondary families, reported and never entering any scale or admission decision: template
occupancy and within-template dispersion, from a train-only per-patient template model whose
`k` is chosen against the patient's own null.

**Ties are read from `event_group_ids`, not from equal rank values.** `event_local_rank` is a
normalised rank among participating contacts, so equal stored values do not recover the tie
structure; the canonical encoding is `recruitment_groups` / `encode_recruitment_matrix` in
`src/topic5_interictal_operator.py`, where contacts sharing a group are tied. A tied pair
contributes **0.5** to precedence.

Support floors are mandatory and frozen: a contact enters the participation and rank families
only above a minimum participation count; a pair enters precedence only above a minimum
co-participation count.

**Each primary family is tested against its own null separately.** A combined score may not
carry the decision when two of the three families were incomputable — that would let a single
correlation coefficient stand in for the repertoire. If fewer than two primary families
resolve, the window is `UNRESOLVED_FAMILIES`.

### 6.3 The three agreements

- `R_random(N)` — two **randomly** assigned halves of the same window: the sampling-noise
  ceiling.
- `R_chrono(N)` — the window's **chronological** first and second halves.
- `R_null(N)` — after permuting contact identity: this patient's own chance level.

A window's verdict is decided by two votes with **different denominators**, and neither vote
has a fallthrough **[rev3]**:

- **above chance** — a strict majority of *resolved* families whose `R_random` median exceeds
  `q95[R_null]`. Failing that majority, the window is `BELOW_CHANCE`.
- **chronology break** — a strict majority of the *above-chance* families only, whose
  `R_chrono` sits below the `R_random` distribution at \(\alpha\). A family that cannot beat
  its own contact-permuted null has no meaningful first-half-versus-second-half comparison to
  cast, so it does not vote here.

Among above-chance windows the outcome is three-way, never two-way:

| chronology vote among above-chance families | window |
| --- | --- |
| strict majority say break | `CHRONOLOGY_BREAK` |
| strict majority say no break | `RELIABLE` |
| neither, i.e. a tie | `UNRESOLVED_FAMILY_DISCORDANCE` |

A tie is the families failing to decide, not evidence of reliability. rev2 returned `RELIABLE`
on a tie, which inflated apparent reliability exactly where the evidence was weakest.

**Cross-window aggregation is a majority, not a mode [rev3].** For each scale:

1. drop windows whose verdict is `UNRESOLVED_FAMILIES`, `UNRESOLVED_FAMILY_DISCORDANCE` or
   otherwise not evaluable — they never vote;
2. require the surviving evaluable count to still reach `min_windows_per_scale`, else the
   scale is `UNRESOLVED_TOO_FEW_WINDOWS`;
3. emit `BELOW_CHANCE`, `RELIABLE` or `CHRONOLOGY_BREAK` only when one of them holds a
   **strict majority of the evaluable windows**;
4. otherwise emit `UNRESOLVED_MIXED_WINDOWS`.

Taking the most frequent label would let 2 of 5 windows name a scale.

**The admissible pattern across the ascending grid is
`BELOW_CHANCE`\* → `RELIABLE`\+ → `CHRONOLOGY_BREAK`\*.** A leading run of `BELOW_CHANCE`
windows is expected and must not force an unresolved verdict — rev1's contiguous-usable-prefix
rule wrongly returned `UNRESOLVED_SCALE` whenever the smallest grid window was too small.
A pattern that does not match (for example reliability returning after a break) is
`UNRESOLVED_NONMONOTONE` and is reported, not silently coerced.

**Scales that could not be evaluated are dropped before the pattern is matched, never
counted as failures.** Two states mean "not evaluated": `UNRESOLVED_TOO_FEW_WINDOWS` and
`UNRESOLVED_FAMILIES`. Both are excluded from the sequence. An earlier draft dropped only the
first, so a single `UNRESOLVED_FAMILIES` at the smallest grid window — the most likely place
for it, since the support floors bite hardest there — would break `leading_ok` and throw the
whole patient to `UNRESOLVED_NONMONOTONE`. That is the same failure the leading-below-chance
rule was written to kill, and it is now closed on both states.

Dropping a scale from the MIDDLE of the grid cannot destroy monotonicity, but it can
fabricate it: `{50: below, 100: reliable, 200: not-evaluated, 500: reliable}` matches the
pattern as though 200 were reliable. That is accepted, but any reported `N_break` or dwell
interval spanning a dropped scale must carry the dropped scale's position, because the true
label there is unknown.

An absolute reliability threshold such as `R ≥ 0.7` is rejected: contact counts range from
about 8 to 16 in this cohort, the noise floor of a rank correlation moves with that, and one
constant would systematically label high-dimensional patients as needing more events.

### 6.4 What counts as an independent window **[rev2]**

200 random splits estimate one window's uncertainty. They are not 200 replicates and never
enter a cohort or patient-level count. Frozen:

- **primary windows are non-overlapping within a session**, tiled from each session start;
- **sliding windows at fractional offsets are sensitivity only** and are labelled as such;
- windows from different sessions of the same patient are pooled, with session recorded;
- a scale is evaluated only when the patient has at least `min_windows_per_scale` resolved
  primary windows at that scale; otherwise that scale is `UNRESOLVED_TOO_FEW_WINDOWS` and is
  excluded from the pattern in §6.3 rather than counted as a failure;
- **the statistical unit is the patient**, never the window and never the split;
- the grid spans 6 event scales × 7 clock scales. Scale selection is **sequential over the
  ascending event grid** — the first `RELIABLE` and the first subsequent break — so no
  maximum is taken over scales, and no multiplicity correction is applied to the selection
  itself. Any *reported* per-scale test statistic is corrected across the 13 scales by
  Holm, and the correction is stated wherever such a statistic appears.

### 6.5 Dwell is an interval, not a point **[rev2]**

The grid is coarse, so the model-free dwell readout is an interval:

\[
N_{\mathrm{dwell},p}\in[\,N_{\mathrm{last\ reliable},p},\ N_{\mathrm{break},p}\,).
\]

Reporting "the dwell is 500 events" from a grid containing 200 and 500 is forbidden; the
admissible statement is that the dwell lies in `[200, 500)`.

Clock grids `ΔT ∈ {300,900,1800,3600,7200,14400,21600}` s are run in parallel and yield
`ΔT_obs,p` and `ΔT_break,p` by the same rules. Equal-event windows control event rate; equal-time
windows measure real duration. Both are reported; neither substitutes for the other.

### 6.6 Backbone versus residual: the scale that actually matters **[rev3]**

The three primary descriptors are computed on raw participation, mean rank and precedence.
Those are dominated by the patient's **stable backbone** — the fixed source, relay and sink
structure that split-half and odd-even analyses already established years ago. Decomposing,

\[
\text{raw descriptor}=\text{stable backbone}+\text{slow-state deviation}.
\]

If the scale curves are run on the raw descriptor, a small window looks "reliable" because the
backbone reproduces, and a large window may never show a chronology break because the backbone
does not drift. Phase 1 would then report a scale that is really a restatement of the known
stable-backbone result, dressed as a slow-state timescale. **That is the failure this section
exists to prevent, and it is why Phase 1 is not open until this is implemented.**

Phase 1 therefore produces **two** scale curves per patient:

- **raw / backbone reliability** — quality control only. It answers "can this window see this
  patient's stable repertoire at all". It yields \(N_{\mathrm{obs,backbone}}\).
- **backbone-residual reliability** — the slow-state scale. The patient's global per-contact
  and per-pair main effects, estimated on the training portion only, are removed from every
  window's descriptors before the agreements are computed. It answers "is the *local deviation*
  from this patient's own backbone reproducible", and yields \(N_{\mathrm{obs,state}}\).

Downstream use is fixed here:

\[
\text{block size}=\max\!\left(N_{\mathrm{obs,backbone}},N_{\mathrm{obs,state}}\right),
\qquad
N_{\mathrm{break}}\ \text{from the residual chronology curve}.
\]

If the residual repertoire is never reliably estimable at any grid scale, the patient's verdict
is **slow state not observable**, and explicitly **not** "the stable network does not exist".
The backbone result stands on its own prior evidence and is not re-litigated here.

**The residual curve's power depends strongly on contact count, and this changes how a negative
verdict may be reported [rev3, measured during R3-C implementation].** Removing the backbone
removes most of the signal that a rank correlation over a handful of contacts can carry, so the
residual test is far weaker than the raw one at small montages. A probe during implementation
put the residual above chance at 12 and 16 contacts and **not** above chance at 6, holding the
injected deviation fixed. This cohort's contact counts run from about 8 to 16, so low-contact
patients will systematically fail the residual test for reasons of power, not biology.

Two consequences are binding:

1. `slow state not observable` must **always** be reported together with that patient's
   residual-curve power — the contact count and the smallest deviation the curve could have
   detected. A bare count of how many patients were "not observable" is forbidden, because it
   would read as evidence against slow states while mostly measuring montage size.
2. Any cohort statement contrasting observable and non-observable patients must show the
   contact-count distribution of both groups. If they differ, the contrast is confounded with
   montage size and must be labelled as such.

## 7. State geometry and its nulls **[rev2]**

Phase 1 emits a frozen `state_geometry` verdict per patient — `few_stable_clusters`,
`continuous_trajectory` or `undetermined` — from block representations at `N_obs,p`. It is
written before Phase 2 runs and selects the Phase 2 family (§8).

rev1 proposed shuffling block row order and re-running KMeans. **KMeans is invariant to row
order, so that is not a cluster null at all.** The frozen nulls are:

- **cluster null** — each descriptor dimension independently given a source-coherent circular
  shift. This preserves every dimension's marginal distribution and its autocorrelation while
  destroying the cross-dimensional co-occurrence that a genuine state produces.
- **continuous null** — a phase-randomised / circular surrogate preserving the smoothness of
  each dimension while destroying the correct temporal pairing between blocks.

Scaling, any dimension reduction and the choice of `k` are fitted on the **train** portion
only and applied unchanged to validation and test.

When the verdict is `undetermined`, **both** model families are run and **both are reported**.
Selecting whichever performed better and declaring the patient a success is prohibited.

## 8. Phase 2 — the slow-state generative model **[rev2]**

### 8.1 The observation is not a dense real matrix

An event is not a `[event, contact]` real matrix. It carries binary participation, a rank
conditional on participating, and tied rank sets. A diagonal Gaussian assigns probability to
impossible events and cannot distinguish *did not participate* from *participated but late*.
The minimum admissible factorisation is

\[
p(x_e\mid z_b)=
p\!\left(m_e\mid z_b\right)\;
p\!\left(r_e,\text{ties}\mid m_e,z_b\right),
\]

with `m_e` the participation mask (per-contact Bernoulli conditioned on the state) and
`(r_e, ties)` the ordering of the participating contacts including tied groups, conditioned on
the mask. Optional template membership is a secondary head and never required.

### 8.2 The causal recursion is locked

\[
h_b=\operatorname{update}(h_{b-1},X_b),
\qquad
X_{b+1}\sim p(X\mid h_b).
\]

A target block never contributes to the state used to predict it. This is a hard invariant
with its own test; a leak here would manufacture the entire result.

### 8.3 Layers

Fast encoder per event `u_e=\operatorname{Enc}(x_e)` keeping participation, conditional rank
and tie group. Slow update once per block,
`h_{b+1}=\operatorname{RNN}(h_b,\operatorname{Pool}\{u_e\},\Delta t_b)`. The decoder emits the
**distribution of the next block's events** under §8.1, and the likelihood sums over every
event in the block.

Family is fixed by the §7 verdict, frozen before Phase 2 runs: `few_stable_clusters` →
semi-Markov with explicit dwell `d_b\sim p(d\mid z_b)`; `continuous_trajectory` → continuous
transition with `Δt`-dependent uncertainty; `undetermined` → both, both reported. Capacity may
not be increased to rescue a failing arm.

## 9. Nuisances, and the event-rate conflict resolved **[rev2]**

rev1 said both that the state modulates event rate and that rate is conditioned away as a
nuisance. Those cannot both hold. Resolution:

- **primary** — the model predicts the **propagation mark** (participation, ordering, ties) of
  each event **conditional on the observed event times**. Event rate is conditioned on, not
  predicted. This is the cleanest question and matches what the descriptors measure.
- **secondary, separate deliverable** — a joint marked point-process analysis in which the
  state also generates the inter-event intervals. Only here may "the state changes the event
  rate" be claimed.

Observation-layer nuisances are time of day (cyclic sine/cosine of local hour, using the
repository's existing `_classify_day_night` / `epoch_to_local_hour` contract), local event
rate, and **elapsed recording time plus a per-recording intercept**.

rev1's `session_index_normalised` is removed: it forced a discrete recording identity into a
linear trend and could not generalise to an unseen recording. A hierarchical per-recording
intercept, or a recording fixed effect where the count is small, replaces it.

Nuisances enter the **observation** layer only. A test asserts that the transition's signature
does not accept them, so time of day can never become a state label.

## 10. Phase 3 — per-patient acceptance

Each admitted patient is adjudicated on its own data:

1. local repertoire change exceeds within-window estimation noise;
2. the state model beats that patient's own stationary null;
3. states reproduce across seeds and across a chronological split;
4. state-conditioned event distributions genuinely differ;
5. dwell time is longer than a random-label run of matched marginals;
6. the state predicts that patient's event distribution over a longer future stretch.

Verdicts: `identifiable`, `unresolved_coverage`, `stationary`, `continuous_state_candidate`,
`switching_state_candidate`. Held-out evaluation is chronological within patient. No
cross-patient pooling adjudicates any individual. Within-session and cross-gap transitions are
scored separately per §4.3.

## 11. Admission, and what 40 blocks does and does not buy **[rev2]**

A patient enters Phase 2 when `N_obs,p` exists **and** it has at least **40 blocks** at
`N_obs,p`.

Forty is a **coverage floor only**. A chronological 60/20/20 split of 40 blocks gives 24/8/8,
which is weak for a two-to-five-state semi-Markov model, and this contract does not pretend
otherwise. The usable range is established empirically by a mandatory synthetic calibration
(§12) that reports recovery rate as a function of state count, dwell length, observation noise
and block count. **A patient whose (state count, dwell, block count) region shows poor
recovery in that calibration is reported as `UNDERPOWERED_FOR_ITS_REGIME`, not as
`stationary`.**

Patients failing the scale test are `UNRESOLVED_SCALE`; those failing the block count are
`UNRESOLVED_INSUFFICIENT_BLOCKS`. Both are explicit unresolved states, never evidence that the
patient has no slow state. The admission denominator is reported before any Phase 2 result is
read.

## 12. Mandatory synthetic calibration **[rev2]**

Before human Phase 2 results are read, the model is calibrated on synthetic block sequences
spanning: state count `{2,3,4,5}`, dwell `{2,5,10,20,50}` blocks, observation noise at three
levels, and block count `{40,80,160,320}`. Reported per cell: state-recovery rate, dwell
recovery, and false-discovery of structure in a stationary sequence.

This calibration defines which human `(state count, dwell, block count)` regions are
interpretable at all, and is the reference for the `UNDERPOWERED_FOR_ITS_REGIME` verdict.

## 13. Cohort layer is prevalence, not mean effect

Sparse SEEG observability is strongly patient-specific. The cohort question is: *in how many
of the 34 patients is the sparse observation sufficient to identify a slow state, and what do
the identified states look like?* Reported: proportion identifiable; each dataset separately;
dwell distributions; each patient's within-patient permutation p-value; the number surviving
FDR; and the specific observability reason for every patient that did not pass. Cohort medians
of a per-patient effect size are not the primary endpoint.

## 14. Strata

Four patients carry 67k–112k events and can host blocks at every grid scale. They are declared
a **deep stratum** here, before any v4.0 outcome, and reported separately. They may not be
presented as the cohort result, and the main cohort may not be quietly replaced by them.

## 15. Phase 4 — block innovation and switching hazard

Only for patients adjudicated `identifiable`. The innovation unit moves from a single event to
a reliable block, `\xi_b=R_b-\mathbb E[R_b\mid z_b]`, and the two tests are
`\xi_b\rightarrow z_{b+1}-F(z_b)` and
`P(z_{b+1}=k\mid z_b,\ \text{cumulative atypical events})`. Order is mandatory: identify
states, show they switch, then ask whether block composition precedes switching. A Phase 4
result is an association. Causal plasticity, synaptic formation and biological learning remain
prohibited; "supports activity-dependent shaping" requires independent replication in a frozen
external dataset and is out of scope.

## 16. Evidence levels

- **S0 — no reliable scale.** No `N_obs,p` exists at any grid window.
- **S1 — reliable local repertoire, stationary.** A scale exists; the state model does not beat
  the patient's stationary null.
- **S2 — identifiable slow state.** Phase 3 checks 1–4 pass.
- **S3 — long-dwelling switching state.** S2 plus dwell longer than the matched random-label
  null and states reproducible across a chronological split.
- **S4 — block composition precedes switching.** S3 plus Phase 4. Association only.

Levels are per patient. A cohort statement reports how many patients reached each level, never
an averaged level. `UNRESOLVED_INSUFFICIENT_BLOCKS` and `UNDERPOWERED_FOR_ITS_REGIME` are not
levels and are never mapped onto S0 or S1.

## 17. SNN relationship

SNN is independent. It is not a Gate, target, prior, label source or ground truth. After both
lines are frozen their observable propagation principles may be compared as a
discussion-level convergence test only.

## 18. Release checklist

Phase 2 execution is released only after these **design**, not outcome, items are machine
recorded:

1. metadata-derived source-interval manifest, with `metadata_gap_seconds` and
   `event_silence_seconds` separated and the unobserved flag on every gap;
2. block manifest, including dropped session remainders and the within-session versus
   cross-gap transition labels;
3. per-patient `N_obs`, `N_break`, `ΔT_obs`, `ΔT_break`, the dwell interval, the three
   agreement curves and the per-scale resolved-window counts;
4. per-patient `state_geometry` verdict, the nulls used, and the family it selects;
5. the admission gate outcome and its denominator;
6. the synthetic calibration table and the interpretable-regime map;
7. the deep-stratum membership list;
8. chronological split indices per patient;
9. all null constructions, nuisance specifications and per-patient acceptance rules;
10. explicit confirmation that no Phase 4 selection appears in the Phase 2 run;
11. config, code, source-list and input hashes.

V2.7 and V3.0 completion are not on this checklist and are not Gates for v4.0.
