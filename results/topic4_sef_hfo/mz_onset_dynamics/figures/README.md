# MZ early-onset dynamics — figures

### mz_onset_natural_trajectories.png

用 E1146 单被试小网络，把「放电疲劳」的强度从零开始一点点**加密**往上扫，看它怎么改造「抑制刹车耗尽 → 失控」这条链。三联图：左（A）最弱疲劳那一档（target frac 0.001、seed 3）的时间过程——一连串正常大小的间期事件（上排 rate 尖峰）每次把去抑制 D（中排，=1−z̄）和疲劳 a（下排）往上顶一格，D 像**楼梯**一样爬到约 0.056 就卡住（离 onset 走廊 ~0.087 还差一截），是「卡在半路的高位平台」、不回落。中（C）D–a 状态平面叠三 seed × 五档疲劳：只有刹车（红，无疲劳）沿 D 轴冲到失控（红星＝run-off 起点，落在走廊 D≈0.087）；疲劳越弱越往右（D 越高），越强越被拐上疲劳轴卡在低 D。右（D）直读「每档疲劳把 D 卡在哪」：a=0 触到 run-off 走廊（红叉 + 阴影带 ~0.087），之后每加强一档就把 D 卡得更低（0.056→0.033→0.020→0.017→0.013）。

**关注点**：三件事——(1) 红线冲到失控 vs 彩色线被疲劳挡住的**梯度**（Panel D 最直读）；(2) 连最弱疲劳（紫，约为 onset 走廊的 65%）都在三 seed 里挡住失控；(3) **没有任何一档在冲高后回落**（都停在平台）。图例 "target frac" 是离线标定目标、不是实现的 a(t)（纵轴才是实现的 a）；"population-averaged" = 全 E 平均、非单细胞。结论：这个最小线性疲劳**能梯度化防住 / 拖住失控，但不能「发作到边缘再收回来」**。

### mz_onset_tau_sensitivity.png

审阅 §5 的追问：把疲劳的**恢复速度**调快（时间常数从 2s 缩到 1s/0.5s、固定 η_m=0.00745），会不会在最靠近临界那档凑出「发作—收住—恢复」的循环？左（A，纵轴裁到 0.13 好看清 0.05–0.10 段）去抑制 D 随时间：恢复慢（2s，蓝）稳卡在 run-off 走廊（虚线，~0.087）以下；恢复中（1s，橙）两 seed 贴线、一个翻过去失控；恢复快（0.5s，红）三 seed 全冲过线（随后 D 飙到 0.6–0.8、出屏）。右（B）每 seed 到达的 D vs 恢复速度（圆=有界平台的最高 D；叉=失控则取**越界时刻**的 D，落在走廊、不是越界后峰值）：平台随恢复变快而升高，然后越界失控。

**关注点**：恢复更快**不是**凑出循环、而是**削弱刹停**——平台一路升到失控走廊再翻车、始终不回落。这把结论钉死：最小线性疲劳**能防不能控**。
