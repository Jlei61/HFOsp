# 数据驱动病理场 — 图说明

复现入口：

```bash
# 先跑仿真（把手放的两个核换成学出来的场，其余一切不动）
python scripts/run_sef_hfo_subject_snn.py --subject epilepsiae_1146 --montage narrow \
  --placement gradient_shared --core-r 1.5 --seed 5 --T 8000 --k-dir 2 \
  --core-field results/topic4_sef_hfo/data_driven_core_field \
  --tag epilepsiae_1146_learned_core_field_cr1p5_s5
# 再画
python scripts/plot_topic4_core_field_learned_vs_manual.py
```

### learned_core_field_readout

回答：**把原来手工摆的两个低阈值核换成从间期数据学出来的场之后，同一张网络还会不会
自发产生正反两个方向的间期事件，事件长什么样，电极上读出来长什么样。**

跟已发表的手放版本 `results/paper-ready-figure/fig4_subject_snn_e1146/figures/fig4_panel_b_bidirectional_readout`
**用同一个 seed（5）、同一套坐标配准、同一批绘图函数**，两张图可以直接并排比较；
唯一的区别就是病理区域是手放的还是学出来的。

四列：

- **pathology along the axis**——病理细胞沿传播轴的分布。红色是手放的两个核（两座分开的峰、
  中间完全空），蓝色是学出来的场（从头平到尾），灰点线是"整条轴均匀铺满"的参照。
  学出来的那条基本贴在灰点线上。
- **model forward / model reverse**——同一次跑里代表性的正向、反向事件。点云颜色是相对点火先后
  （深紫=最早，黄=最晚）；**红色半透明带 = 学出来的病理场本身**（装了 90% 病理细胞的那块区域），
  白星 = 该事件实际的起火点（最早点火的那 1% 细胞的质心），橙/青连线是虚拟电极。
  **这两格里没有任何手放核的标记**——这次跑的机制输入只有那条学出来的带，画圈会误导。
  带子是斜的是对的：显示坐标只把片子平移到中心、不做旋转，共享轴本身就在 −22.8°；
  带的中线过两个核的中点。
- **model virtual-SEEG**——**同一次跑（学出来的场）**的连续 30–80 Hz 虚拟 SEEG，不是病人真实记录。
  橙色 = 沿轴那根电极杆，青色 = 横向那根；暖色底纹标正向事件，浅蓝底纹标反向事件。

同一 seed 上的对照数字（写进 metadata）：

| | 事件数 | 干净事件 | 正/反 | 两方向在组织上的相关 | 两方向在触点上的相关 |
|---|---|---|---|---|---|
| 手放的两个核 | 34 | 5 | 1/4 | −0.748 | −0.685 |
| 学出来的场 | 5 | 5 | 2/3 | −0.863 | −0.755 |

**关注点**：第一列看**形状差多远**——学出来的是一条贯通全轴的细丝，不是两个分开的核；
中间两列和最后一列看**功能上有没有塌掉**——在这个 seed 上没有：正反两个方向都还在，
而且两个方向彼此相反的程度不比手放的差。事件总数从 34 掉到 5（但全部干净），这是要留意的
副作用，不是本图的结论。**单 seed 单次跑，只能读作可行性示例，不能读作队列证据。**

⚠️ **"两个方向相反"这个量在单次 8 秒的跑里估不稳，本图上的 −0.755 不可当作结论。**
同一个场在 4 张没见过的网络上逐个算：反向事件数只有 0 / 2 / 1 / 1 个，相关系数因此从
−0.627 一路摆到 **+0.918**，中位数 +0.655。判"两个方向是不是两套相反的模式"必须堆够事件数
——见下面那张 120 网络的图，以及那里关于"这个数依赖纳入哪些触点"的警告。

### learned_core_field_validation

回答：**学出来的场自发跑出来的那些事件，会不会自然分成两类，这两类是不是对应正反两个方向，
以及它们像不像病人真实的两套间期模板。**

输入：**120 个独立网络 × 8 秒自发活动 = 960 秒**，共 562 个可定向事件
（正 392 / 反 170）。不重跑仿真，只消费 `readout_epilepsiae_1146_learned_core_field_pool_s{21..140}`。

三块：

- **左（事件热图）**——每一列是一次事件，颜色是该触点在这次事件里的先后名次
  （深紫=最早，黄=最晚），灰格 = 该次事件没招募到这个触点。红色分界线是 KMeans 分成两簇的位置。
- **中（两簇的名次剖面）**——两簇各自的平均名次±标准差。两条线交叉 = 两簇是相反的顺序。
- **右（模型×数据相似性矩阵）**——模型两套模板 vs 病人两套真实模板的秩相关。
  星号是通道置换检验的显著性。对角红、非对角蓝 = 模型正向对上数据正向、反向对上反向。

数字（对照已发表的手放版）：

| | 手放的两个核 | 学出来的场 |
|---|---|---|
| 协议 | **分开驱动的干预阳性对照**（正向只取"只放源核"那次，反向只取"只放汇核"那次） | **自发**（同一次跑里两个方向自己出现） |
| 事件数 | 222（正 103 / 反 119），21 网络 | 562（正 392 / 反 170），120 网络 |
| 簇内方向纯度（in-sample） | 1.000 | **0.988** |
| 簇内事件顺序一致度 | 0.919 | 0.813 |
| 两套模型模板彼此相关 | −0.983 | **−0.569** |
| 模型×数据 对角 | +0.98 / +0.84 | +0.82 / +0.66 |
| 模型×数据 非对角 | −1.00 / −0.96 | −0.94 / −0.80 |

**关注点**：结构成立 —— 无监督分出的两簇，**簇内方向纯度 98.8%（in-sample）**，
两簇模板在显示的 11 个触点上彼此相反（−0.569），且分别对上病人的两套真实模板（四格全部显著）。
**但预注册的合同门不过**，见下。

⚠️⚠️ **本图上的 −0.569 是显示过滤后 11 个触点上的数，不是预注册合同门的判定。**
合同（spec §10.3 第 2 条）要求在**冻结的 15 触点支撑集**上算，那里是 **−0.130，不过 ≤ −0.2 的门**
（`../bidirectional_gate_pooled.json`）。四条门里第 1、3、4 条过，**第 2 条不过 ⇒ 整个门不过**。

⚠️ **归因（2026-08-08 更正，先前写的是错的）**：先前说"横向 4 个触点被填成同一个值"——
**不对**，审计代码取两方向的交集，15 个触点全在里面，秩次都是实测的。
真正原因是**观测太稀疏**：15 个触点里有 6 个的**正向**平均秩次只由 **2–10 个事件**估出
（远端 `ICL9/10/11` 正向 2–10 次、横杆 `SCL6-9` 每方向 2–6 次）。于是这个相关随纳入门槛剧烈变化：
15 触点 −0.130 / 每方向≥5 次的 9 触点 −0.650 / ≥25 次的 8 触点 −0.500 / ≥100 次的 7 触点 −0.250。
**不存在单一"真值"；引用任何一个都必须写明算在哪些触点上。**

⚠️ **98.8% 是同一批事件上的簇内方向纯度（in-sample cluster purity），不是预测准确率**——
KMeans 就是在这批事件上拟合的。要写准确率必须按网络种子交叉验证，本轮没做。

因此**不得**写成 "数据驱动的场复现了双模板 repertoire"；能写的是
"模型在沿轴那根杆的近端有大量内容、在远端与横杆上几乎没有内容；
在观测充分的那些触点上两个方向是两套相反的模式"。

⚠️ **两张图不是同一个协议，不能直接比数值大小。** 手放那版是**分开驱动的干预阳性对照**：
方向标签由"这次放的是哪个核"给定，所以纯度 1.000 和 −0.983 在很大程度上由协议决定。
它是合法且有用的对照（证明该底物在分开驱动下能出两套相反模板），
**但不能**作为"自发双向 repertoire"的证据。
学出来的场没有两个核可以分开放，只能自发跑 —— 这是**更难的检验**，
它的 0.988 / −0.569 是在同一次仿真里自己长出来的。

⚠️ **两个方向不对称，且正向传得不够远**：正:反 = 2.31:1（反向占 30.2%，95% 区间 26.5–34.2%）；
正向事件平均只招募 6.6 个触点、几乎到不了远端（ICL9–11 参与率 0.5–2.6%），
反向事件招募 8.3 个、能覆盖全杆（64–78%）。横向那根杆的 4 个触点参与率均 < 1.5%，
被 15% 参与率门槛滤掉，本图是 ICL 单杆 11 触点的读出。
